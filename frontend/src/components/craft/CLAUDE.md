# components/craft — /craft, /craft/new (my deskterior list + creation wizard)

Paired with `src/api/craft.ts` (list), `src/api/placement.ts`, `src/api/product.ts` (catalog).

The two `paths:`-scoped rule files that carried this folder's incident history (`craft-wizard.md`, `craft-list-publish.md`) were deleted (rules-diet 2026-08-14) — every constraint they held is in the 지속 이슈 section below, which is now the record.

## Persistent issues

- **`/craft/new` desk choice is a two-stage picker**: the first screen only picks a mode (`직접 입력` / `책상 선택`), `다음` enters it, double-click enters immediately. Custom opens only the specification form; template mode shows only searchable catalog desks (6 per page). **Keep these paths separate — do not put the custom card back into the paginated product grid.**
  - **Double-click races its own preceding single-click side effect (2026-08-06)** — a dblclick fires two ordinary `click`s first, and their queued `requestAnimationFrame` scrolls landed *after* the dblclick's `onApplied()`, silently scrolling back down. Any scroll/DOM mutation scheduled from `onClick` on that card needs the same cancel-before-double-fire treatment (`cancelRevealNext()`).
- **Browser back must step through the wizard's own navigation stack** (2026-08-06 user report) — `useHistoryBackGuard` checks `step > 1` then `pickerMode !== null`, and is **off entirely** at the base screen so a real back-press leaves naturally.
  - **Never pass `enabled: true` unconditionally from mount — it bricks entry navigation in dev.** StrictMode's mount → cleanup → re-run makes the cleanup's `history.back()` land as a genuine back-press, and the page bounces straight back to `/craft` on mount. Conditional toggling is safe; `EditorTopBar` survives only because its `enabled` is false at mount.
  - `isLeavingWizard` must force-disable the guard before the final `router.push('/simulator?...')`, or the unmount cleanup's `history.back()` fires after the forward navigation and snaps back to a blank `/craft/new`.
- **`CraftDeskPicker.tsx` cards use the real catalog API `GET /api/v1/products?specType=DESK`** — never promote filters into the path (api-spec §11). The old local procedural catalog (`three/scene/product.ts`) had string ids, not backend `product.id` (Long), so it is unusable for placement-create.
- **Materials come from the `GET /desk-textures` master since 2026-08-01 (DERO-335)** — admin additions need no FE deploy. The stopgap tables (`DESK_TEXTURE_ID_TO_MATERIAL`/`MATERIAL_TO_DESK_TEXTURE_ID`/`DESK_MATERIAL_IDS`) are **deleted — do not revive**; skin canon is `deskTextureSkin`/`deskSkinForTextureId` in `three/core/deskConfig.ts`. **Trap**: `DeskConfig.materialId` is an unread fallback slot, so `'oak'` there ≠ "material stuck on oak" — persisted canon is `DeskConfig.deskTextureId`. The `materialSkin` passed to the preview must be reference-stable, or every render rebuilds and disposes the whole desk group.
- **`CraftDeskPreviewScene.tsx` rebuilds `buildDesk` per keystroke** via `useMemo` (an effect + `setState` trips `react-hooks/set-state-in-effect`). `sanitizeDim()` clamps to 1mm so mid-typing 0/empty never reaches `buildDesk` with degenerate geometry — **unrelated to `validateCustomDesk`'s submit-time `DESK_RANGE` (100–3000mm); don't touch range validation chasing a flicker bug.**
- **`getDeskProjects()` (`api/craft.ts`) is browser-only — from a server component it silently returns someone else's list.** The token lives only in browser memory (ADR-0005 decision 3) and `GET /placements` is optionally authenticated, returning **PUBLIC only** instead of 401. So `app/craft/page.tsx` stays metadata/shell and `CraftDeskCollectionLoader.tsx` (client) fetches. **Never re-collapse failures with `.catch(() => [])`** — that hides an auth failure as an empty list. ⚠️ **Not resolved**: others' PUBLIC placements are still mixed in (no `?owner` param yet — REQ-USR-02). (The server-component caller `app/collection/new/page.tsx` is gone — that route was deleted 2026-08-11.)
- **`DeskProject.budgetKrw` is the budget, never the desk's price** — it is `placement.budgetKrw`, which the `/craft/new` wizard defaults to 750,000 and almost nobody edits, so rendering it as "가격" made every desk show the same number (2026-08-10, in the since-deleted `/collection/new`; the field used to be named `price`). The only real total is `GET /placements/{id}/estimate` → `totalPriceKrw` (`usePlacementEstimate`); the list response carries no total, so a list-wide price needs a backend field, not an N+1. ⚠️ **Not resolved**: `CraftDeskCollection`'s "가격 순" sort still sorts by budget.
- **`DeskProject.thumbnailUrl` is 16:9, not square, since 2026-08-02** — `captureFullCanvas()` re-renders at `camera.aspect = 16/9` + `setSize(1600, 900, false)` and the backend sizes the AI concept render from those pixels. **Re-render, not resize/crop.**
- **`thumbnailUrl` is a backend-issued stable public URL with a deterministic key, so it arrives even when no file exists.** The detail returns `null` for an empty `thumbnail_key`, but **the list has no such distinction** — a truthiness-only render shows broken images; pass `common/RemoteImage`'s `fallback` ("미리보기 없음") like `DeskProjectCard.tsx`. Thumbnail upload is a 2-step presign whose bytes bypass the backend, so it **fails locally without S3 credentials**.
- **The collection publish entry lives on the card since 2026-08-11 (D33 · ADR-0036)** — `DeskPublishControl.tsx` renders "컬렉션에 올리기" on `PRIVATE` and "다시 올리기" on `FAILED` (same sheet, different wording — there is no separate retry UI), "업로드 중" on `PENDING`, "공개 취소" on `PUBLIC`; non-numeric (optimistic local) ids render nothing at all. **Never put the button inside `DeskProjectCard`'s `<Link>`** — keep it a sibling.
  - **`CollectionPublishSheet.tsx` saves the placement first, then publishes** — title/description are canon on `placement` (`GET /placements/{id}` → `toPlacementSnapshot` → `PUT /placements/{id}` **with `version` restored**, since the helper nulls it for remix and null is an unconditional 409), then `PUT .../feed-entry` with the tags. Publishing first can bake the old title into the AI image; the localStorage sidecar that used to hold those two fields is deleted.
  - **The sheet's one `GET /placements/{id}` serves both jobs** — the snapshot to save and the screenshot gate (`thumbnailUrl === null` only ever shows up on the detail; the list URL is deterministic and always populated).
  - **Server value wins for `DeskProject.publishStatus`** — the merge prefers local otherwise, and re-saving an already-public placement makes the card lie. Don't delete that overwrite line.
  - **The card does not poll — `common/UploadWatcherBootstrap.tsx` does**; the badge is derived from `uploadNotificationsStore` and falls back to the server value when a watch folds. Unpublish must call `forgetPlacement`, or a dead 404 link stays in the bell.
  - **Don't gate on "no screenshot" from list values** — the list `thumbnailUrl` is always populated, and a per-card detail fetch would make a 100-item list N+1. The gate belongs to the sheet, which already fetches that one placement's detail.

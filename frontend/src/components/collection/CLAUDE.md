# src/components/collection — /collection gallery + detail

Inherits `frontend/CLAUDE.md`. Routes: `/collection` (gallery), `/collection/[collectionId]` (detail), `/collection/[collectionId]/edit` (title/description/tags). **There is no upload route** — publishing starts in the workshop (`craft/CollectionPublishSheet.tsx`, D33 · ADR-0036); `/collection/new` was deleted 2026-08-11 and the gallery's "데스크 올리기" button now routes to `/craft`. Community's placement attachment + "가져오기" (D26) moved here — community no longer references real placements (`src/components/community/CLAUDE.md`).

This file is the canon for this folder. Two `paths:`-scoped rule files
(`.claude/rules/frontend/collection-{detail,gallery}.md`) hold only the handful of constraints
*not* repeated here; `collection-upload.md` was deleted with its target files (rules-diet 2026-08-14).

## Data model

- `CollectionPost` (`types.ts`) **always** carries a real backend `placement.id` as `placementId` — this domain exists to publish and take other people's desks.
- **`CollectionPost.id` IS `String(placement.id)`** — the detail route refetches by it, so any divergence 404s every card.
- **The list is real `GET /placements?publishStatus=PUBLIC`** (DERO-339), fetched by `CollectionGalleryLoader` (client) because sort and the accumulating cursor are state. **An empty feed can be correct** — uploading leaves the placement `PENDING`, not `PUBLIC` (ADR-0015).
- **"Used items" are real placement items** — the mock field `CollectionPost.usedProductIds` is **deleted; do not revive it**. `CollectionDetail` is the single fetch owner and `CollectionUsedItems` is display-only: **never put a fetch back into a display component**. The header count is the distinct-product count (`usedItems.length`), never the instance total; a product 404 silently drops that card; the client computes no price total (`PlacementEstimateSummary` is canon).
- **"이 배치의 실사 사진" is the desk-feed reverse lookup** (`CollectionRealPhotos` → `GET /desk-feeds?placementId=`, ADR-0033 decision 4). **Desk-feed posts only** — community story posts are not necessarily that desk. It fetches itself (the one display-component exception here: nothing else on this page needs the data) and renders **nothing at all** when no post is attached.
- **The cover is the primary AI imagination image, not a 3D screenshot** — `primaryImageUrl` from the list response. **The server summary's `thumbnailUrl` (simulator screenshot) is never used in the feed** (that is the craft card's, ADR-0015 decision 7), and **do not call `GET /placements/{id}/generated-images` per card**.
- **All covers go through `CollectionCoverImage.tsx`** — it picks remote (`common/RemoteImage`, next/image) vs bundled sample and owns the fallback. **Never branch on the thumbnail URL being truthy** — the key is deterministic, so a never-captured placement still returns a URL; `onError` fallback is the whole reason that component exists.
- **Title, description and tags are all server values now** (D33 · ADR-0036, 2026-08-11): title/description are `placement.title`/`description` (written by the workshop sheet and by `CollectionEditForm` via `PUT /placements/{id}`), tags are `placement_hashtag` (`PUT .../feed-entry/tags`). The `collectionMyPostsStore` sidecar and every decoration of the server list with local values are **deleted — do not revive** (its premise, "the placement has no collection fields", was wrong from the start). Cards are still built from the server list only: **never draw a card the server did not return** (a `PENDING` placement has no imagination image and would show the raw screenshot).
- **Search and the tag chip filter are both server-side** (`GET /placements?q=` ADR-0027 · `?hashtag=`, 2026-08-07) and both live in the loader, because changing either must restart paging from the first cursor. **A 503 `PLACEMENT_SEARCH_UNAVAILABLE` is a banner, never an empty list** (ADR-0019 decision 6), and the infinite-scroll sentinel must not render while it is up. The leading `#` is stripped **once, on the frontend** (`utils/searchQuery.ts`).
- **Open dependencies blocking full real mode** (schema/endpoint side, not being solved now): bookmark counts, `photoId` → `placement.thumbnail_key`, auth scheme (#129), response envelope (#135), and `PUT`/`DELETE /placements/{id}/feed-entry` (REQ-COM-04). Full rationale: `docs/context/api-spec.md` "비워둔 것".

## 지속 이슈

- **The gallery masonry is fixed flex columns + index round-robin, never CSS columns** — column-wise fill redistributes every card when infinite scroll appends a page, so cards jump mid-scroll (2026-08-06 user report). Same lesson as community's rule.
- **The 5-tag cap (`COLLECTION_MAX_TAGS`) is a frontend display decision; the server caps at 20 — do not remove it** (pre-cap localStorage records still hold 6+). `collectionDemoTags.ts` is deleted (DERO-493) — **do not revive**; an empty chip row means nobody has tagged anything.
- **Any money line is the estimate (`usePlacementEstimate` → `totalPriceKrw`), never `DeskProject.budgetKrw`** — the wizard default (750,000) sits on nearly every desk.
- **`CollectionEditForm` writes tags first, then title/description**, and the title write puts `version` back (a null version is an unconditional 409). **Do not reuse `PUT .../feed-entry` for editing** — that call is the publish/retry button (sends `PUBLIC` back to `PENDING`, regenerates the image, charges quota).
- **Never fabricate a card from the 202** — `createCollectionPost`/`CreateCollectionPostInput` are deleted, do not revive. `PENDING → PUBLIC` polling belongs to the global `common/UploadWatcherBootstrap.tsx`, not this screen.
- **The client loader is mandatory for anything reading `getDeskProjects()`** — the token lives only in browser memory (ADR-0005), so a server component 401s and used to fall back to mocks showing other people's desks (2026-08-02). Distinguish `'failed'` from a successful empty array.
- **Bookmark/like toggles are gated by `requireAuth()`** on gallery and detail. Card bookmarks **send a body-less PUT** — `{groupId: null}` would silently move an already-grouped bookmark. **Like counts render only when logged in** — the read itself 401s, so 0 cannot be asserted (detail like/bookmark/comment are real APIs, DERO-342).
- **"가져오기" is `POST /placements/{id}/remixes` (DERO-343), detail-only, and `disabled` on my own desk.** Ownership compares `session.userId` with `post.authorId` **as strings** (also used by 수정/삭제).
- **The detail shows one money line, the total** — `PlacementEstimateSummary` with `showBudget={false}`. The simulator's `EstimatePanel` keeps budget + overrun; confirm which screen before restoring a budget line.
- **`CollectionGeneratedImages`'s `IMAGES_PER_UPLOAD` must equal the backend's `FeedEntryService.IMAGES_PER_UPLOAD`** — larger leaks re-publish history into the current batch, smaller cuts fresh images.
- **No components are shared with community** (user-confirmed) — avatars use shared `common/PersonAvatar.tsx`, and collection never imports from `community/`.
- **`/collection` and `/collection/[collectionId]` have no `loading.tsx`** — the blank body is what "the photos don't show" reports actually were. `/craft` has the same gap.

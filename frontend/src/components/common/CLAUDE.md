# src/components/common — global/shared components

Inherits root `frontend/CLAUDE.md`. Only UI belonging to no single domain/page (toast, button, filter, transition).

Automation-browser measurement traps load from `.claude/rules/frontend/qa-browser-measurement.md`. The four other rule files that carried this folder's incident history were deleted (rules-diet 2026-08-14) — their constraints are the Persistent issues below, which are now the record.

## Navigation — no animation; `TransitionNavigator` controls scroll + history only

- `data-scroll-top="true"` is the explicit navigation override: every link in `layout/TopNavbar.tsx` carries it, so header navigation always scrolls to document top, including clicking the already-active route again.
- **Moving between product categories (sidebar) uses `router.replace`; everything else uses `router.push` (2026-08-03, user request)** — repeated category switches must leave one history entry so Back returns straight to "전체 제품". Decide with `url.pathname === '/product' && url.searchParams.has('category')` true for **both** current location and destination; if only one side has a category (enter/leave), use `push`.
- **For a category-only `/product` change (tag/view unchanged) that decision is executed via raw `history.pushState`/`replaceState`, never the Next router** — calling it re-runs `page.tsx` on every click even though the filtering is 100% client-side, which read as "clicking a category navigates to a new page". The bypass (`isProductCategoryOnlyChange`) dispatches `PRODUCT_CATEGORY_CHANGE_EVENT` instead. **Any other query param wanting the same treatment must join that guard**, or it silently keeps the slow path. Consumer side + the required `popstate` resync: `components/product/CLAUDE.md`.
- Product category clicks do not use the navigator's document-top scroll — `ProductGrid` scrolls its `scroll-mt-24` list heading into view after two animation frames.
- **`PageTransition.tsx` and `SectionReveal.tsx` were deleted (2026-08-02, user confirmed)** — no fade/slide/delay on any internal navigation. `TransitionNavigator.tsx` is all that remains and does **scroll control only**, intercepting link clicks in the **capture phase** (a bubble-phase `preventDefault` is too late under React 19). **All three attempts to make navigation itself an animation failed** (AnimatePresence, frozen `children`, View Transitions) — do not retry them.
- Header is `sticky top-0`, so any `scrollIntoView` target needs `scroll-mt-24` to clear the 64px header. Changing a list filter changes document height and jumps the scroll — anchor it by saving `getBoundingClientRect().top` before the click and correcting with `window.scrollBy` in a `useLayoutEffect`.
- `key={...}` on list pages is now purely "remount on filter change to reset internal search/sort state".

## Persistent issues

- **Every remote image goes through `RemoteImage.tsx` (next/image) — never a bare `<img src={url}>`** (ADR-0035 결정 5). Its `fallback` prop replaces every screen's old local failure state and keys the failure on the `src` itself. Only three `<img>` remain by design: two `blob:` upload previews and `product/ProductCategoryIcon`'s bundled icon. **`fill` needs a parent sized independently of the image** — where the image itself gives the box its height (masonry cards), pass `width`/`height` or the parent collapses to 0.

- **Always wrap `position: fixed` overlays (modal, toast, always-on chrome) in `BodyPortal`.** Any non-`none` `translate`/`transform`/`filter` on an ancestor makes it the containing block, so `fixed inset-0` stretches to the document — **even `translate-y-0` counts, because 0 is not `none`**. For UI rendered **at page load**, add a mount guard (`isMounted`) too: the portal returns `null` during SSR.
- **`ScrollProgress` is not decoration — it is this site's *only* scrollbar** (`html.hide-scrollbar` removes the native one), so it needs hand-implemented dragging. Constraints that will bite: hit area max **20px (`w-5`)** or it steals `ScrollToTopButton`'s clicks; `setPointerCapture` or the drag dies off-track; keep `aria-hidden`.
- **Nothing scroll-linked may go through React state or a CSS transition** — rAF + direct style write, or `position: sticky` so the compositor owns it. Breaking this is what made the whole site's scrolling feel bad once (DERO-630).
- **`DecorGlowBackground` must be a direct child of the page's root `relative overflow-hidden` wrapper, before any content** — its glow is `absolute top-0`, so a `relative` section ancestor moves it down (2026-08-09 user report; the same misplacement had already been fixed on 2026-08-08 and came back). It also must not be gated on section data — the lighting is page chrome.
- **`UploadWatcherBootstrap.tsx` is the root layout's fourth bootstrap** — polls `PENDING` placements from any screen and feeds the top bell. It must await rehydrate, keep **one** timer with boolean deps and re-read state via `getState()` inside a tick. `/simulator` is not excepted — only `/simulator/thumbnail-render` is. **Measure the deadline only after confirming `PENDING`** — measuring first folds an already-`PUBLIC` placement for a user returning to a long-closed tab and loses its completion notification (`startedAt` is persisted as epoch ms for the same reason).
- **Notifications are `started`·`succeeded`·`failed` only** — `timedOut` ('아직 처리 중이에요') described our problem, not a result, and was removed 2026-08-02; a deadline overrun now folds silently via `dropWatch`. `PUBLISH_POLL_TIMEOUT_MS` is **300s**, equal to backend `app.image.generation.read-timeout`, so a generation finishing at that boundary is missed with no notification (the user must refresh). Do not revive a fourth notification type.
- **Never call zustand `set()` (or any side effect) inside a `useState` updater** — React runs updaters during the render phase and StrictMode runs them twice, so the store mutates mid-render (`Cannot update a component while rendering a different component`) and the effect fires twice. Put it in the handler body. **Lint cannot catch this position** — it passed `lint`, `typecheck` and `build` (2026-08-02 `UploadNotificationBell`).
- **zustand `persist` does not sync across tabs** — each tab polls and resolves its own uploads; the later writer can overwrite another tab's read markers. Accepted for now.
- **In the QA automation browser the tab is `document.hidden === true`**, so rAF halts, layout reads go stale, `setTimeout` is throttled and `window.scrollTo()` fires **no** `scroll` event. Verify through DOM state and inline `style`, dispatch the event yourself, and measure only click-relative deltas inside one script execution. Visual checks need a real user browser.
- **Check `SortDropdown`'s open direction inside an `overflow-y-auto` container** — the list clips at the boundary (`z-index` does not help; this is clipping, not stacking). Use `openDirection="up"` and change only the anchor — a flex wrapper makes it squash instead of clip.
- **Do not measure `Stepper.tsx` step content height from `children` deps** — a child expanding via its own state keeps the same reference, so the effect never re-runs and the fixed `height` + `overflow:hidden` clips it invisible. Watch real DOM height with `ResizeObserver`.
- **`AutoCarousel` writes its transform through a ref, and its mount-time positioning effects must be `useLayoutEffect` with `isAnimated` starting `false`** — otherwise it visibly slides sideways after load then snaps back. `GAP_PX` must equal the track's gap; `forceLoop` stays on for the promo banner or the carousel switches off at ≤3 items.
- **Focus-ring canon is the combination in `ErrorState.tsx`** — `focus-visible:outline-primary-600 focus-visible:outline-2 focus-visible:outline-offset-2`. Do not define a new utility.
- Looking up a selector directly in `sheet.cssRules` always returns empty — Tailwind v4 nests utilities inside a single `@layer utilities { ... }` rule, so recurse into `rule.cssRules`. Concluding "the rule doesn't exist" without recursing is a misdiagnosis.

# src/components/community — community list, detail, write, edit

Inherits `frontend/CLAUDE.md`. `/community` (list) · `/community/[postId]` (detail) · `/community/new` (write) · `/community/[postId]/edit` (edit).
A post is title + free markdown body (`CommunityPost.content`) — no template (3D placement) selection.

This file is the canon for this folder. Two `paths:`-scoped rule files in `.claude/rules/frontend/` hold only what is *not* repeated here — `community-editor.md` (`<`/`>` escaping, photo-count reservations, no mid-draft remount, objectURL revoke) and `community-list-detail.md` (`requireAuth` gate, `min-w-0` truncate, the single `#` strip).

## Data model (2026-07-30 full redesign, 2026-08-03 real API)

- **Everything is the real `/posts` API since 2026-08-03 (DERO-345)** — list/detail/create/edit/delete go through `src/api/post.ts` (raw calls) and `src/api/community.ts` (CommunityPost view-model conversion). The mock generator `communityPosts.ts` (+ `constants/communityPosts.ts`, `communityAuthors.ts`) was **deleted 2026-08-03**.
- **`[[placement:ID]]` is the only placement reference in a body (ADR-0013 결정 1·2)** — a missing id renders a **"삭제된 배치입니다" placeholder, not `null`**. Insert candidates are only own PUBLIC placements; **no publish-toggle UI is built** (publishing is done by `/craft` upload).
- **There is no third body token — per-photo product tags live in a junction table (ADR-0040)**. `[[products:…]]` shipped and was reverted the same day; **do not reintroduce a body token for per-photo data**.
- **The writing UI is a Tiptap WYSIWYG but the stored format is a plain markdown string** — `serializeEditorContent.ts` writes it, `parseEditorContent.ts` reads it back, so **write and edit are the same WYSIWYG** (DERO-605). The pair's contract is **lossless round-trip over the syntax the serializer emits** (`tests/parseEditorContent.test.ts`): add a syntax to one side and you must add it to the other, or that syntax silently dies the first time someone edits the post.
- **The image src stored in a body is a never-expiring `imageKey`, not a URL** — `imageUrl` is presigned with a 15-minute TTL, so embedding it **breaks the post after 15 minutes**. Resolve at render via the `(imageKey → imageUrl)` map (`PostContent`'s `imageUrls` prop); **list responses carry no such map**. Presign requires the post to exist, so a new post must save → upload → re-save with keys.
- Use only `react-markdown`'s default export (the synchronous `Markdown`) — `MarkdownHooks` uses hooks and cannot run in a server component.

## Persistent issues

- **`PostRichEditor` and `PostContent` have an outside consumer since 2026-08-11 — desk feed** (`components/desk-feed/`, D32 revision · ADR-0034 made that domain post-isomorphic). Changing the editor handle, the serialized string format, or `PostContent`'s props breaks `/desk-feed/new`·`/desk-feed/[postId]` too. `PostRichEditorHandle.insertImages` exists **only** for desk feed's large top upload zone — community screens never call it. The gallery/card components are still not shared with anything.
- **The only `<iframe>` a body can produce is a YouTube embed** (DERO-616) — the swap is in `PostContent`'s `p` renderer and the host check uses `URL`, not a regex. Do not widen the sanitize allowlist: this is an SSR public page.
- **`PostContent` remounts every image subtree on every parent re-render** (its `components` object is rebuilt each render) — that is why the desk-feed rail re-queries markers per scroll instead of holding nodes (DERO-628). Do not attach anything to nodes captured at mount.
- **In-editor typography is a manual mirror of `PostContent`'s renderers** (`globals.css` `.tiptap` block, DERO-627) — change a size/weight/color in `PostContent.tsx` and you must change the `.tiptap` rule too, or the WYSIWYG silently drifts from the rendered post.
- **Never insert an image without `toImageAlt`** — a `]`/`)` in the alt makes the saved `![alt](key)` unparseable and **the next edit-and-save silently drops that photo**. `PostRichEditor` sanitizes at the one insert point; new insert paths go through it.
- **Never let the `placementEmbed` node's `placement` snapshot leak into the saved string** — it holds a 15-minute presigned `thumbnailUrl`; serialization reads id-like attrs only, and any new Tiptap node must keep that rule.
- **Replacing the editor document from code: park the string in a ref, apply it in an effect** (`pendingBodyRef` + `[content]` effect in both edit forms) — the `(key → URL)` map is a prop, fresh only after the next render. Insert straight from the upload callback and the just-uploaded photo renders dead. Related: `initialContent` is read once at mount, so the forms render the editor only after the post **and** its `[[placement:ID]]` snapshots have loaded — draw it earlier and live placements flash "삭제된 배치입니다".
- **`PostRichEditorToolbar` must render even while `editor` is `null`** — `useEditor({ immediatelyRender: false })` leaves it null briefly after mount, so gating the toolbar makes it appear only after a click in the body.
- **`@tiptap/starter-kit` (v3) already bundles Underline and Link** — installing the standalone extensions logs "Duplicate extension names"; configure via `StarterKit.configure(...)`.
- **`setContent` must never surface the post-replace selection as a user image pick (DERO-633)** — ProseMirror maps the old selection into the new doc; landing on an image atom makes it a NodeSelection, and emitting that opened the desk-feed tag panel on the wrong (usually top) photo, saving tags to it. The handle resets to a text selection and emits `onSelectedImageChange(null)`; guard: `e2e/desk-feed-photo-tag.spec.ts`.
- **`toPlainText` in `communityContent.ts` is substitution-order dependent** — image-markdown removal must run **before** symbol removal, else upload filenames leak into preview cards. Guard: `tests/communityContent.test.ts`.
- **Comments have no server** — they live in `communityCommentsStore` (session memory), so a card's count is `server commentCount + this session`. Select with the store's `EMPTY_COMMENTS` reference, never `?? []` (infinite loop).
- **Never go back to CSS columns (masonry) for the list grid** — column-wise fill against newest-first data makes the first row read #1·#5·#9. Backend sort key is `id`, not `createdAt`.
- **A 503 `POST_SEARCH_UNAVAILABLE` is its own list state, never an empty list** — no fallback by decision (ADR-0019 결정 6). Search is `GET /posts?q=`, debounced 300ms, and the debounced value must stay a dependency of both the fetch effect and `handleLoadMore`.
- **The detail-page like is one labeled button between the body and the comments, not a heart beside the title** (2026-08-03 user request) — do not "restore" a second toggle next to `<h1>`.
- **Detail (`/community/[postId]`) is client-fetched** — `src/api/community.ts` is an async seam, so nothing may call it during render; `generateMetadata` therefore ships fixed copy.

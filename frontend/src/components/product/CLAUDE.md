# components/product — /product catalog and category nav

`ProductGrid.tsx` (list, search, sort, category filter) renders **one layout — always with the left sidebar (`ProductCategorySidebar.tsx`, line icons)** for both the all view (`/product`) and a category view (`?category=X`). The promo banner (`ProductPromoBanner.tsx`, `PROMO_ITEMS`, 4 items) is always on top; the carousel below it appears **only in the all view**.

The two `paths:`-scoped rule files that carried this folder's measurements and ticket history (`product-list-paging.md`, `product-display.md`) were deleted (rules-diet 2026-08-14) — every constraint they held is in Persistent issues below, which is now the record.

## Persistent issues

- **The list is server cursor paging in real mode since 2026-08-05** — `ProductGrid` calls `useCatalogPage(categoryIds, appliedQuery)` and `ProductCardGrid` grows per **server page**; `page.tsx` no longer prefetches. **Search is server-side too** (`GET /products?q=`, Elasticsearch + Nori, ADR-0019, DERO-384): **do not re-apply the client name filter (`matchesQuery`) to real products** — an ES hit spaced differently ('모니터암' → '모니터 암') or matched by brand would drop back out. **There is no fallback by decision** (ADR-0019 decision 6): a 503 `PRODUCT_SEARCH_UNAVAILABLE` must surface as `state.status === 'search-unavailable'`, never as 0 results. Sort and like filters still cover **loaded** pages only.
  - **The "N개" next to the heading is the server `CursorPage.totalCount`, not `visibleProducts.length`** — `totalCount` arrives on the first page only (a later page's 0 must not overwrite it) and multi-id 소분류 streams must be **summed**. Guarded by `tests/catalogPageState.test.ts`.
  - **Mock mode keeps the old path** (static array, client slicing, client category + name filter); the hook is a no-op there.
  - **The observer `useEffect` deps must include `visibleCount`** — otherwise a still-visible sentinel never fires again and paging measurably stalls at 12. **Reset the expanded count by `key` remount**, never `setVisibleCount` in an effect (React Compiler lint error).
- **검색창 추천어 드롭다운(`product-search-suggestions`, DERO-385)은 확정 전 입력값(`searchQuery`)을 따라간다** — 목록에 나가는 `appliedQuery`와 다른 축이다(목록은 '검색' 버튼/Enter로만 움직인다). Enter는 **짚은 항목이 있을 때만** 훅이 가져간다. 로직은 시뮬레이터와 공유하는 `hooks/useSearchSuggestions.ts`이고 이 화면은 마크업만 갖는다.
- **Sidebar category clicks are a pure client-side filter, not a Next navigation (2026-08-03)** — `common/TransitionNavigator.tsx` updates the URL with raw `history.pushState`/`replaceState` and broadcasts `PRODUCT_CATEGORY_CHANGE_EVENT` (`constants/productCategoryGroup.ts`); `ProductGrid` holds `categoryOverride` and resyncs it on `popstate`. **A future `/product` query param needing the same treatment must join the `tag`/`view`-must-match guard in `isProductCategoryOnlyChange`**, or it silently keeps the slow path. After the event, scroll `listHeadingRef` into view (two animation frames), not document top.
- **Mock-derived display values were deleted on purpose — do not revive them without the API field first**: ★rating, review count, the sorts '리뷰 많은순'/'인기순' (now '등록순'), '현재 N개의 데스크테리어에서 사용 중', and list-card like counts. Reviving usage counts needs a backend `COUNT(DISTINCT placement_id)` over `placed_item` + `placement_desk`; reviving list like counts needs `likeCount` in the list response (the detail's `GET /products/{id}/like` **401s when logged out**, hence `CountPillToggle.count` is `number | null`).
- **The carousel is '새로 등록된 제품' (reverse registration order), not '최근 많이 팔린 상품'** — **do not bring that naming back while there is no sales field.**
- **Never `??`-fallback brand/price** — `productContent.ts`'s marketing mock holds the same fields with **different values** for half the mock catalog, so `product.priceKrw ?? content.priceKrw` silently flips mock screens. Canon is `getDisplayBrand`/`getDisplayPriceKrw`/`getDisplayDescription`, **split on registration**: id in `PRODUCT_CONTENT` → mock value, else real `ProductSpec`. Same rule for every new display field.
- **ARM detail dimensions come from `ARM_FALLBACK_DIMS_MM` because the `arm` table has no box columns** — `buildSpecRows` emits real arm specs instead. Do not revert them "to match other products".
- **Categories are a static frontend canon since 2026-08-05 — `GET /categories` is never called.** `PRODUCT_CATEGORY_GROUPS` (`src/constants/productCategoryGroup.ts`) is shared with `simulator/LibraryPanel.tsx`; `?category=` carries a group key, a sub key, or a comma-joined list of sub keys of one group. Real-mode filtering is server-side via hardcoded live-DB `categoryId`s (roots 52–61, subs 62–78 — the repo seed's flat 900–908 is stale and shipped a day of "every category empty"). **A group sends its root id only** (root+children would duplicate products), and the client name filter must **not** also run on real products. **Do not delete the hidden `desk` group** — a desk product's breadcrumb would fall back to "기타".
- **Category icons: canon is the 3D webp set `src/assets/3D-icons/*.webp`, statically imported in `ProductCategoryIcon.tsx`** (line-SVG fallback only for desk/water-bottle). Promo images are `assets/product/promo/{productId}-{slug}.png` — keep the filename and `PROMO_ITEMS[].productId` in sync.
- **Detail specs are plain label/value lines with no container box; the bottom action row fills the column width** — sizes are hardcoded in the non-`bare` branch of `common/CountPillToggle.tsx`, whose only consumer is this screen; add a `size` prop when another screen needs one.
- **목록 카드 썸네일은 `object-cover`, 상세는 `object-contain` — 의도한 분기다 (2026-08-04).** `ProductCard.tsx`의 이미지만 `object-cover`(박동규 요청); `ProductHeroImage.tsx`·`ProductImageGallery.tsx`·`simulator/LibraryPanel.tsx`의 `.lib-thumb`는 `object-contain` 유지 — **"다른 제품 화면과 맞춘다"며 되돌리지 말 것.** `ProductCard`는 `/product` 그리드·캐러셀·마이페이지 찜 목록(`mypage/ProductWishlistPanel.tsx`) 셋이 공유하므로 클래스 한 줄이 목록 3곳에 걸린다.
- **Below `md` the sidebar becomes `ProductCategoryChipRail`** (a named export of `ProductCategorySidebar.tsx`); its chips are the same `<Link>`, so they inherit the `router.replace` rule for category moves (`common/CLAUDE.md`) — never call `router.push` directly. **Sidebar rows show 대분류 only**; 소분류 is the chip row above the grid. `CategoryNavRow`'s chevron/accordion code survives in `ProductCategorySidebar.tsx` but never renders (no nav item passes `children`) — **if it is ever revived, the leaf list must not repeat a "전체" entry for the root**, which the root row above it already is (2026-08-03 duplicate-menu-item bug).
- **Empty and error states are separate (2026-08-02)** — load failure renders `common/ErrorState` (retry `router.refresh()`), an empty list renders copy + a '전체 제품 보러가기' link. **Focus-ring canon is the `common/ErrorState.tsx` combination** `focus-visible:outline-primary-600 focus-visible:outline-2 focus-visible:outline-offset-2`; do not define a new utility, and put the ring on the `<Link>`, not the `overflow-hidden` image frame.
- **The promo banner auto-advances and the carousel does not** — keep the promo's `forceLoop` on, or it switches off entirely at ≤3 items. **The sidebar `<aside>` scrolls independently** via `max-h-[calc(100vh-8rem)] overflow-y-auto` alone — no wheel handler, no second scroll container.
- Never put a literal control character in source — a raw NUL in `ProductGrid.tsx`'s key separator made **`grep` treat the file as binary and silently match nothing**. `RelatedDeskteriorSection.tsx`/`ProductCategoryShowcase.tsx` were deleted by user request — reviving either needs a new endpoint and 박동규's approval.

# api/auth — real Auth Adapter

`actualAdapter.ts` is where ADR-0005 (social OAuth, JWT access/refresh rotation) actually talks to the backend. Paired with `port.ts` (contract) and `accessTokenHolder.ts` (in-memory token, same module-singleton pattern as `authRuntime.ts`). `refreshCoordinator.ts` is wired into the 401 auto-rotation in `api/client.ts` — the instance is injected at boot by `components/auth/authRuntime.ts` via `setApiRefreshCoordinator` (a direct `client.ts` → `actualAdapter` import would be circular).

## Standing issues / traps

- **`authorize()` returns a Promise that never resolves.** Real OAuth is a full-page redirect, so the browser leaves this document. Resolving here makes `AuthEntryRoute` immediately call `router.replace('/auth/callback')`, racing SPA navigation against the real browser redirect and flashing `/auth/callback` before a new session exists (2026-07-29).
- **Takes `navigate` / `readCallbackError` as injected options instead of touching `window`.** `vitest.config.ts` pins `tests/` to `environment: 'node'`, so there is no `window` — DI instead of adding jsdom. Real usage (`authRuntime.ts`) passes nothing and the defaults use `window.location`.
- **Backend auth-failure bodies have no `errors` field at all** — `ProblemDetails.of` fills only `code` and `instance`; `errors` is added only on validation failures (`GlobalExceptionHandler`). `parseProblemDetail` in `utils/auth/problemDetail.ts` requires `errors` as an own property, so every real 401/403 collapses into `UNCLASSIFIED_API_ERROR` (which is why `currentSession()` cannot recognize anonymous as anonymous). The 401 auto-rotation in `api/client.ts` sidesteps this by not using `mapAuthProblemDetail` and classifying from status + `problem.code` itself — once `parseProblemDetail` is fixed, delete that classification and go back to the canonical mapper (found 2026-07-31, not fixed).
- **Backend `ProblemDetail` omits `type` from the body entirely when it is the default `about:blank`** (Spring serialization default; see the comment in `backend/dero-api` `ProblemDetails.java`). `parseProblemDetail` originally required `type` as a string, so before the fix every 401/403 would have collapsed into `unclassifiedApiError` (never actually triggered — `actualAdapter` was fail-closed and never fetched). Found and fixed while wiring `actualAdapter` for real (2026-07-29) — missing `type` now defaults to `'about:blank'`.

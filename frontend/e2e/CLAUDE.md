# e2e — Playwright scenario tests

Simulator placement / lighting / joints / screen transitions. Units (vitest) live in `tests/`; real browser only here.
Screenshot capture, pixel judgment and SwiftShader measurement traps are **not** here — see `.claude/rules/frontend/canvas-capture.md`.

## Standing issues

- **Specs visiting `/simulator` MUST call `seedCoachTourSeen(page)` (`helpers/tour.ts`) in `beforeEach`, before the first `goto`** — Playwright starts with empty localStorage, so every simulator spec is a "first visit" and the coachmark overlay (`.sim-coach-root`, `z-index:15`) covers the viewport and eats every click as "next step". The symptom is not "element not found" but clicks on `rail-*`/`lib-card-*`/`save-layout` that appear to land and do nothing. The helper `addInitScript`s `dero-simulator-tour` = `{"state":{"seen":true},"version":1}` (zustand persist envelope) next to `stubAuthenticatedSession`; `grep -l seedCoachTourSeen` for the current set. **`simulator-tour.spec.ts` deliberately omits it** (it reproduces first visit), as do `oauth.spec.ts`'s anonymous case (bounces to `/login`) and `/simulator/thumbnail-render` (no `SimHud`).
- **`NEXT_PUBLIC_API_MODE=real` in `frontend/.env.local` times out every simulator spec at boot — not the spec's fault.** e2e runs without a backend (ADR-0016 decision 5), so real mode makes `initEngine` → `loadRealCatalog` → `GET /products` throw `ApiError: 로그인이 필요합니다` as an **unhandledRejection** and `window.__sim.ready` never sets. The only symptom is a 30s `waitForFunction` timeout, easily misread as "my last edit broke boot" — **also run an untouched spec (`manipulate.spec.ts`); if it dies too it's the environment.** Override in the shell (`NEXT_PUBLIC_API_MODE=mock npx playwright test …`; Next never overwrites an existing `process.env`), never by editing the personal `.env.local`. `stubAuthenticatedSession` does not cover it (only `/auth/refresh` + `/users/me`), and mock alone is no guarantee — the boot degradation below still bites (2026-08-02, 6/6 failed).
- **`/simulator`, `/craft`, `/craft/new` sit behind `AuthGate` (decision 8 / D14)** — `goto` without a session stub bounces to `/login?returnTo=…` and the scene never mounts. `helpers/auth.ts`: `stubAuthenticatedSession(page)` in `test.beforeEach` (`/auth/refresh` success + `/users/me`, the order `AuthBootstrap` calls at boot). Login round-trip specs need `stubLoginRoundTrip` — **succeeding at refresh from the start stands the session up before `/login` renders, `AuthEntryRoute` replaces straight to returnTo, the OAuth button never enters the DOM, and the click waits 60s.** Logout specs need `stubLogoutRoundTrip`: `TopNavbar` calls `window.location.reload()`, so a still-succeeding refresh logs the user back in. The only DOM signal for a closed gate is `[data-auth-gate="checking"|"anonymous"|"error"]`, and it disappears entirely once open (2026-07-31).
- **Anonymous `POST /auth/refresh` 401 is always logged as a console error by Chrome** — normal contract (AUTH_REFRESH_INVALID), same against a real backend. Filter with `collectConsoleErrors(page, [EXPECTED_401_CONSOLE_NOISE])` (2026-07-31).
- `data-intent` is on provider buttons (`OAuthProviderButton`) as well as panels (`section`) — bare `[data-intent="login"]` is a strict-mode violation; use `section[data-intent="login"]`. `TopNavbar` has **no** `data-auth-status` attribute — detect anonymous via `header a[href="/login"]` present and `header a[href="/mypage"]` absent (2026-07-31).
- Use `page.goto('/simulator')`: a path in `baseURL` is overwritten by an absolute `goto('/…')`, landing on the root page — no scene and no 404 either (2026-07-22).
- No `import.meta` — Next's `package.json` has no `"type": "module"`, so specs load as CJS. Build paths from `process.cwd()` (= `frontend/`) (2026-07-22).
- Spec changes to desk config must re-place props — `setDesk(config)` calls `clearPlaced()` (see `src/three/CLAUDE.md`, 2026-07-21).
- Visual judgment (render look, color, shadow) cannot be replaced by a machine gate — needs 박동규 (human-in-the-loop).

## Rail / library selectors

- **The left category rail (`EditorSidebar`) hides the lighting / library / view panels by default** — click `getByTestId('rail-product'|'rail-light'|'rail-view')` first, then the inner testids (`room-light`, `wall-*`, `cam-*`, `category-*`, `hud-camera`, `hud-library`) enter the DOM.
- Selection detail (`hud-selection`, `rotate-slider`, `detach-button`, `joint-*`) is **not** a rail category — the right-hand `SelectedItemPanel` shows it automatically whenever `selectedItemId` is set, via `window.__sim.selectItem(id)` or a click, no extra click needed.
- Save (`save-layout`), undo/redo (`undo-move`/`redo-move`) and contour lines (`contour-lines`) are always-visible rail actions, not categories — click directly. Only exit (`exit-simulator`) stays top-right.
- The estimate is a right-side always-on popup (`estimate-panel`, `EstimatePanel.tsx`), **not** a rail item, keyed by product spec rather than placed instance (`estimate-item-{specId}`, `estimate-include-{specId}`, `estimate-fold`, `estimate-close`, `estimate-reopen`).
- **Product categories are the static 10-group canon in `constants/productCategoryGroup.ts`** — `category-all` plus 9 group keys (read them there, do not hardcode). A group with 소분류 shows multi-select chips (`subcategory-{key}`) under the breadcrumb. No tile starts active — clicking any one **replaces** the grid with `lib-breadcrumb` + `hud-gallery` (never both visible; `lib-breadcrumb-back` returns), so a drag always needs `rail-product` → `category-{key}` → `lib-card-*`, never a default-gallery shortcut.
- **Flyouts unmount immediately on close** — pressing `rail-product` again or `library-close` drops them from the DOM at once, so no delay wait before `toBeHidden()`.
- Do not trust `boundingBox()` right after expanding a category — until the expand animation finishes (~1.4s on headless SwiftShader) the card is clipped by `overflow-x:hidden` and fails hit-testing, but `boundingBox()` returns the pre-clip layout box and the drag lands on the canvas. Wait via actionability (`hover()`), not a fixed delay (2026-07-25 DERO-156).
- `page.mouse.down()` does not start a library-card drag — pointerdown reaches the canvas and is read as orbit. Dispatch `PointerEvent('pointerdown')` on the card element directly (confirm via `placedCount` increase) (2026-07-25 DERO-159).

## Running the suite

- Full suite alongside a dev server or real Chrome (QA) → SwiftShader contention, placement spec times out at 60s (2x reproduced; alone it passes in 45s). Kill the dev server and QA Chrome before e2e (2026-07-20).
- **Back-to-back full suites degrade `boot()`** — the same code goes 13s/test on run 1 to over 60s on run 3, killing **untouched** specs with "Test timeout of 60000ms exceeded". Tell-tale: all bare timeouts, no assertion failures, and the failing specs move between runs — suspect the environment. SIGTERM on playwright orphans the webServer and browsers and starves the next run; recover with `pkill -f "playwright test"`, check `lsof -ti:3000`, then run smaller batches (2026-07-26 DERO-160).
- **At most one canvas pointer-drag test per spec file** — a library-card → canvas real drag takes 55s alone but exceeds 120s as the 9th spec in a file, while neighbouring specs stay at 11–16s (so it is not session accumulation: each drag is 10 pointermoves × ghost-preview render, expensive on SwiftShader). To add one, use a separate spec file with a single drag (2026-07-26 DERO-160).

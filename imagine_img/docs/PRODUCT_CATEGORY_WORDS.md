# 카테고리 → 프롬프트 단어 표

DB 카테고리 코드 20종을 CLIP 이 읽는 영어 명사로 바꾸는 표. 정의는
[app/generation/product_categories.py](../app/generation/product_categories.py).

**아직 거의 비어 있다.** 코드가 미등록이어도 워커는 돌아가고, 응답 `warnings` 에
`unverified prompt word ... — add it to CATEGORY_WORDS` 가 남는다.

---

## 왜 표가 필요한가

`productCategories` 에 온 코드를 소문자로 바꿔 쓰면 대부분 맞는다 (`DESK_LAMP` → `desk lamp`).
문제는 **안 맞는 경우를 자동으로는 알 수 없다**는 것이다.

```text
TUMBLER → 'tumbler'      CLIP 이 곡예사로도 읽어 텀블러가 각진 검은 덩어리가 됨
TUMBLER → 'water bottle' 제대로 된 무광 보온병                          ← 실측 2026-08-01
```

번역기로는 이걸 못 걸러낸다. 사람이 결과를 보고 채워야 한다.

## 칸 채우는 법

### 프롬프트 단어

- **영어 일반명사, 1~2 토큰.** 브랜드·모델명은 넣지 않는다 (제품 정체성은 3D 가 정한다)
- COCO/ImageNet 에 있는 흔한 단어가 안전하다 — `potted plant`, `mug`, `keyboard`, `chair`
- 다의어를 피한다. 이게 `tumbler` 가 실패한 이유다
- 형용사를 붙이지 않는다. `articulated desk lamp` 는 3 토큰을 쓰면서 `desk lamp` 보다
  나은 게 없다. 토큰이 밀리면 다른 카테고리가 통째로 빠진다

### 실루엣 등급

**`AMBIGUOUS` 가 먼저 자리를 받는다.** 이름이 없으면 다른 카테고리의 물건이 되는 것들이다.

| 등급 | 뜻 | 실측된 예 |
|---|---|---|
| `AMBIGUOUS` | 이름이 없으면 다른 카테고리가 된다 | 프록시 화분(초록색 구) → 금속 손잡이 · 프록시 스탠드(원뿔+막대) → 거울 · 키보드(납작한 판) → 접힌 수건 |
| `READABLE` | 이름 없이도 카테고리는 유지된다 | 머그(손잡이) · 텀블러(원통) · 모니터(받침 있는 사각) |

**등급을 모르면 비워둔다.** 미등록 코드는 `AMBIGUOUS` 로 취급된다 — 이름을 줘서
잃는 것은 자리 하나지만, 안 줘서 잃는 것은 그 물건이 다른 물건이 되는 것이다.

### 등급을 실제로 정하는 방법

추측하지 말고 재는 게 낫다. 그 카테고리가 들어 있는 실제 GLB 렌더 한 장으로:

```powershell
# 이름을 준 경우
.\.venv\Scripts\python.exe -m app.cli generate <캡처> --job-id with-name --products "<단어>,..."
# 이름을 뺀 경우
.\.venv\Scripts\python.exe -m app.cli generate <캡처> --job-id without --products "<나머지만>"
```

두 결과에서 그 물건의 **카테고리가 유지되는지** 본다. 유지되면 `READABLE`,
다른 물건이 되면 `AMBIGUOUS`. 색이나 모델이 달라지는 것은 등급과 무관하다 —
보존 기준이 "카테고리만 맞으면 된다" 이기 때문이다 (2026-08-02 결정).

## 표에 없어도 되는 경우

**화면의 0.3% 미만**을 차지하는 카테고리는 표에 넣어도 쓰이지 않는다.
그 크기는 SDXL 잠재공간에서 7×7 픽셀도 안 되어 이름을 줘도 그려낼 해상도가 없다.

```text
생성 1152x960 → VAE 8배 다운샘플 → 잠재 144x120
0.3% = 약 57x57 px = 잠재 7x7   ← 하한
0.1% = 약 33x33 px = 잠재 4x4   ← 무엇을 그리든 뭉갠다
```

이런 카테고리는 워커가 후보에서 빼고 `warnings` 에 남긴다. 자리를 아껴서
그릴 수 있는 물건에 쓴다.

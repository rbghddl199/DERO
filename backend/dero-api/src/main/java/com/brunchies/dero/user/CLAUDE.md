# user — social-login user aggregate

`User` is the root. General mapping rules: `backend/CLAUDE.md`; column canon: `docs/context/erd.md`.

## Traps

- **Renaming an entity field means grepping the DTO factories and tests that call its getter — the commit diff will not show them.** 2026-07-29 `f088e99` renamed `User.profileImageUrl` to `profileImageKey` (D24 — store only our own uploaded key, not the social provider's photo), but that diff contained only `User.java`, `erd.md` and 3 auth files; `UserMeResponse.from()` (old getter) and `UserServiceTest` (old 5-arg `User.create(...)`) were left broken and only surfaced later as compile errors (DERO-252 follow-up). When reviewing a field rename, run `git grep <old field name>` for missed call sites.
- **In `SecurityConfig` the `/api/v1/users/me` tree must come before the `/api/v1/users/*` permitAll.** `*` matches one segment, so it also matches `"me"` — reverse the order and `GET /users/me` opens to anonymous, and `UserController.userId()`'s `Long.valueOf("anonymousUser")` returns **500, not 401**. Rules evaluate in declaration order (same spot as `/products/*/like`). Regression test: `FollowIntegrationTest.내_정보는_익명에게_401`. Also `/users/{id}/followers` and `/following` are not opened by `/users/*` (single segment), so they have **their own lines**.
- **`GET /users/me/image-quota` code lives in the `image` package, not `user`** (`ImageQuotaService`, `UserImageQuotaController`). The count comes from `generated_image` and the dependency direction is one-way `image → user`, so that table is invisible here — same call as `feed-entry`, whose path is `/placements/...` but whose package is `image` (`image/CLAUDE.md`). **Do not pull `GeneratedImageRepository` into `user`** — `LayerDependencyTest` blocks it mechanically.
- **Day-boundary computation exists in two places** — `ImageQuotaService.getQuota` (usage shown on screen) and `FeedEntryService.requireWithinDailyQuota` (the 429 gate) each call `OffsetDateTime.now().truncatedTo(DAYS)`. Change one only and the screen says "0 left" while uploads still succeed (or vice versa). They were left split solely because DERO-354 was working `image` concurrently — cleanup pending.
- **Never expose `profileImageKey` raw in a response** — per the file-serving decision in `docs/context/architecture-map.md` ("the WAS assembles the complete URL at issue time"), `UserService.getMe()` builds a presigned GET URL via `PresignPort.presignGet(key)` and puts it in `UserMeResponse`. Do not put URL assembly in the `User` entity (entities do not know the storage port).
- **Withdrawal (`DELETE /users/me`, 2026-08-06) is soft delete only, and it never touches session state.** `User.withdraw()` flips `status` to `INACTIVE` + `softDelete()` (`UserStatus.INACTIVE`'s own doc comment already said "탈퇴는 deleted_at이 따로 표현한다" — the enum value was waiting for this). `UserController`/`UserService` do **not** call `RefreshTokenService.revokeAll()` or clear the refresh cookie — `user` cannot depend on `auth` (`LayerDependencyTest`, ADR-0007), so that would be a layer violation. The frontend calls `DELETE /users/me` then immediately `POST /auth/logout` (already-existing, already-idempotent) to finish clearing the session — don't "simplify" this into one backend call without re-litigating the layer rule first.

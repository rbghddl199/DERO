# placement — placement aggregate

`Placement` is the root; `PlacementDesk`·`PlacedItem` live inside it. **Prevention lines only** — the old evidence file (measurements, tickets, failure narratives) was deleted 2026-08-14 (rules-diet 10). General mapping rules `backend/CLAUDE.md`, column SoT `docs/context/erd.md` "### 5. 배치", judgment rules `docs/context/compatibility.md`.

## Traps

- **`PlacementJudge` splits subtypes with `instanceof` on `PlacedItem.product`, so a LAZY proxy silently sends every branch false and the judgment rows vanish** — the symptom is "zero violations", which reads as a pass. Attaching it to a read-only placement requires `join fetch` down to the spec subtype.
  - **`loadDeskProduct`·`loadProducts` need `Hibernate.unproxy`** — after `findForUpdateById` hydrates `desk`·`items`, a later `findAllById` hands back those same base-type proxies and the desk 400s with `PLACEMENT_INVALID_DESK_PRODUCT` despite `spec_type=DESK`.
- **Judgment reason strings must match the TS mirror (`frontend/src/three/core/collision.ts`) letter for letter.** `frontend/tests/fixtures/judgment.json` checks **substrings only**, so wording diverges on screen while the contract test stays green. Never copy the fixture into the backend — that erases the drift detector.
- **NULL in `placement_desk.edge_thickness_mm` means "same as top thickness", not 0** — reading it as 0 corrupts judgment ①'s input. Use `PlacementDesk.effectiveEdgeThicknessMm()`, never the field.
- **`placed_item.joint_values` is `Map<String, Double>`, not a record** — joint keys come per product from `asset.rig_manifest`, so the key set is not fixed. **Store driver joints only** (dependents are recomputed on load) and **do not index the column**.
- **`placed_item.rotation_deg` is `BigDecimal` (`NUMERIC(6,2)`)** — explicit exception to "angles are `INT`". Truncating flips a borderline placement from compatible to violating on reload.
- **`placed_item.pitch_deg` is the one snapshot field *not* `@NotNull` on `ItemSnapshot`** — absent folds to `0` deliberately and the ±75° clamp is the client's job, so do not make it required and do not add a range check (ADR-0023 decision 3).
- **`publish_status` (renamed from `visibility`) has 4 values; `PUBLIC`·`FAILED` are server-decided only.** The publish gate sits on the `PRIVATE` → `PENDING` transition, so **never let the request snapshot carry publish status** — that bypasses the queue.
- **Do not create new enums** — `frame_type` reuses `product.FrameType`, `surface_type` reuses `product.MountSurface` (that direction is allowed, ADR-0007).
- **`@Version` goes on `Placement` only.** A save is a whole-scene snapshot, so the root's single `version` is the only conflict detector; per-child versions split the lock unit and a desk-only save stops detecting conflicts. Never fill it in a static factory.
- **Unmount before deleting a `placed_item`** — `mounted_to_placed_item_id` is a self-referential FK with `NO ACTION`. `is_vesa_mounted` and that column **must always move together**, so touch them only through `mountVesaTo()`/`unmount()`; mount state is judgment input, and a mismatch flips a passing placement into a violation on reload.
- **`cascade` only inside this aggregate.** `user`·`product`·`desk_texture`·`sourcePlacement` are other roots — cascading on `sourcePlacement` would **delete the original when a remix is deleted**.
- **Collection initialization rules out class-level `@Builder`** — `Placement.items`' initializer becomes `@Builder.Default` and JPA's no-args path then leaves the collection null. Use `@Builder(access = PRIVATE)` on the constructor.
- **Remix copying and mount remapping live only in `Placement.copyOf`** — a copy whose `mounted_to_placed_item_id` still points at an original weaves the two placements into one graph, invisibly in the response. Insert sorted so the mount target comes first (FK is `NOT DEFERRABLE`).
- **The save snapshot does not accept `isVesaMounted` — presence of `mountedToRef` is the mount state** (ADR-0009 §3). Accepting both opens the "mounted but no target" state the entity exists to block. It stays in the detail response.
- **Authorization is on (`anyRequest().authenticated()`), and permitAll is scoped to `HttpMethod.GET` on `/placements` and `/placements/*` only** — `*` is one segment, so `/{id}/thumbnail` is closed; **widening the matcher to `/api/v1/placements/**` opens writes wholesale.**
- **On optionally-authenticated paths `Authentication` is `AnonymousAuthenticationToken`, not `null`** — use `AuthenticatedUserId.orNull` (under `@WebMvcTest` it really is `null`, so accept both). **A NULL `placement.user` and a NULL anonymous `userId` also compare equal**, so write `:userId is not null` in JPQL.
- **Do not force `@Version` increment with `@Lock(OPTIMISTIC_FORCE_INCREMENT)` — `PlacementRepository.advanceVersion` (bulk UPDATE) is the place.** Forcing it is still required: `placement.items` is the `mappedBy` inverse, so an items-only change never dirties the root. **Re-read the placement afterwards** (`clearAutomatically`).
- **Write non-`@Version` fields (`thumbnail_key`·`like_count`) with the repository's bulk UPDATEs** — entity methods let dirty checking bump the version and permanently 409 the owner's saves. `Placement.registerThumbnail` is pre-persist assembly only.
- **`updated_at` is stamped by the `advanceVersion` bulk UPDATE** — left to dirty checking, an items-only save keeps it NULL forever (same `mappedBy` cause). Bulk UPDATE skips the auditing listener, so it takes timestamp and actor as arguments; NULL at creation is normal.
- **Do not rely on how much `version` grows in a save response** — one save can bump it by 2. The contract is only "echo the response value back".
- **The thumbnail key is deterministic per placement** (`placement-thumbnails/{placementId}.png`) — that is what proves a registered key is the caller's own, so accepting an arbitrary key lets someone point their placement at another user's file.
- **The list's visibility condition lives in exactly one place, `PlacementRepositoryImpl.visibleTo`, and the count query calls it too** — separate conditions make the count include other people's private rows. **Never filter as post-processing in the service**: the page shrinks and the cursor drifts. `?owner`·`?publishStatus`·`?ids` always AND with visibility.
  - **When unauthenticated, do not add the ownership term at all** — `NULL = NULL` would let an anonymous caller pass as owner of a withdrawn user's placement.
- **The list cursor is composite `(sort key, id)`** — a bare sort key pushes items around inside ties. The axis lives in two files (`PlacementSort.cursorValueOf`, `PlacementRepositoryImpl.orderOf`/`cursorAfter`), so adding a sort means editing both.
- **Bookmark flags and `primaryImageUrl` are read with native SQL for dependency direction, not performance** — `placement_bookmark` and `generated_image` are upper aggregates, so a Java type reference would be backflow. **Cost: changing those tables breaks this at runtime with no compile error** — review `findBookmarkRows`·`findAllBookmarkRows`·`findPrimaryImageRows` when touching them.
  - **`bookmarkedIds` distinguishes `null` (no filter) from empty (matches nothing)** — collapsing empty to no-filter hands a bookmark-less user the whole feed.
  - **`bookmarkGroupId` is `null` when bookmarked but ungrouped** — decide with `containsKey`, not `get`.
- **`PlacementSummaryResponse.totalPriceKrw` is the desk's real value; `budgetKrw` is the user's budget** — the sum comes from `PlacementEstimateService.totalPriceKrwByIds`, **the only place that counts it**. Batch-read over the page's id set, **never per-card**.
- **`PlacementSummaryResponse.tags` uses batch fetch and `?hashtag` filters with an `exists` subquery — never a join**, which would multiply rows and drift the cursor page size.
- **Before dropping an expand-phase source column, ask which rows the *old* code wrote after the backfill ran** — during blue-green the old WAS keeps writing the old shape. Hence three deploys for the wall migration (V8 → V9 → V10 DROP), not two.

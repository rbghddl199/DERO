# 요구사항 명세서 — 데스크테리어 시뮬레이터 MVP

> **살아있는 문서** — 갱신은 이 파일을 직접 수정한다(날짜 스냅샷 신규 생성 금지). 주요 변경 근거는 docs/CONTEXT.md 결정 기록(D번호)으로 남긴다. 최종 갱신: 2026-08-08.
> 상위 문서: `docs/PERSONAS.md` (페르소나·검증 가설), `docs/CONTEXT.md` (결정 기록 D1~D30).
> 우선순위: **Must**(H1~H3 가설 검증 경로, 미배포 불가) / **Should**(첫 배포 포함, 지연 시 후속 릴리스 이월 가능) / **Could**(여유 시).
> 근거 열의 `P1-PN1` 등은 페르소나 문서의 페인 ID.

## 1. 개요

책상 위를 꾸미고 싶지만 실제로 구매까지 이어지지 못하는 사람이 많다. 설문 응답자의 69.2%가 "무엇을 사야 할지 모른다"고 답했고 53.8%는 비용 부담을 주요 장벽으로 꼽았다. 경험자 역시 모니터암 클램프가 상판 두께에 맞지 않아 반품하거나 장비를 추가할 때마다 규격표를 수동으로 비교해야 하는 번거로움을 겪는다. 본 서비스는 실측 규격 기반 3D 데스크 시뮬레이터로, 책상부터 소품·장비까지 실측 규격 제품을 드래그 앤 드롭으로 배치하고 클램프-상판·VESA·하중 호환성을 판정하며 실시간 견적을 제공한다. 구매 전에 배치 결과와 비용을 눈으로 확인해 "사기 전 망설임"과 "구매 실패"를 동시에 줄이는 것이 핵심 목표다. 이 문서는 해당 서비스의 MVP 요구사항을 정의한다. MVP는 핵심 가설 두 가지를 시장에서 빠르게 검증하는 첫 배포 버전이다. 따라서 범위는 가설 검증에 필요한 최소 기능에 한정하고 검증 결과에 따라 후속 버전에서 확장한다.

### 검증 가설

- **H1**: 3D 배치 미리보기 + 실시간 견적이 "사기 전 망설임"을 해소해 구매 결정을 앞당긴다. (P1)
- **H2**: 클램프·VESA·하중 호환성 판정이 구매 실패(반품)를 막는다. (P2, 경쟁사 미제공)
- **H3**: 사용자 스토리 공유(게시글)가 재방문을 만든다. (P1)

## 2. 사용자 시나리오

### 시나리오 A — 첫 데스크테리어 (P1 김준서)

김준서는 하루 8시간 넘게 책상 앞에서 일하지만 데스크테리어는 유튜브 셋업 영상을 저장해 두는 것이 전부다. 장바구니에 소품을 담았다가 "이게 내 책상에 맞을까" 확신이 없어 비우기를 반복한다. 서비스에 진입한 김준서는 커뮤니티에서 마음에 드는 템플릿을 발견하고 내 데스크로 복사한다. 라이브러리에서 자기 책상과 같은 모델을 끌어다 놓자 3D 뷰에 실측 스케일 책상이 나타나고 템플릿의 소품들이 그 위에 배치된다. 마우스패드 크기가 마음에 들지 않아 다른 제품으로 교체하고 모니터 스탠드 위치를 드래그로 조정한다. 화면 하단의 실시간 견적이 예산 범위 안에 들어오는 것을 확인하고, 배치 결과를 저장한 뒤 견적에 표시된 금액을 기준으로 실제 구매를 결정한다. 마음에 든 배치는 업로드해 데스크 피드에 올리고, 그때 AI가 만들어 준 실사 상상도가 자기 배치의 얼굴이 된다. (2026-07-31 D27 개정 — 종전 시나리오는 "AI 상상도로 미리 보고 → 저장 → 구매 결정"이었다. 상상도가 **구매 결정의 입력에서 공유의 산출물로** 성격이 바뀌었고, 완성된 모습 확인은 실측 스케일 3D 씬이 맡는다.)

### 시나리오 B — 장비 추가 (P2 박현우)

박현우는 듀얼 모니터 환경을 쓰는 경험자로, 과거에 모니터암 클램프가 상판 두께에 맞지 않아 반품한 적이 있다. 새 모니터암을 추가하려는데 규격표를 일일이 비교하기가 번거롭다. 서비스에 접속한 박현우는 라이브러리에서 자기 책상 모델을 골라 배치하고 기존에 배치된 장비를 불러온다. 추가하려는 모니터암을 검색해 책상 위에 놓자 호환성 판정이 "불가"로 표시된다. 클램프 최대 허용 두께가 이 책상의 물림 두께보다 얇다는 구체적 사유가 함께 나타난다. 시스템이 같은 VESA 규격에 물림 두께가 맞는 대안 제품 목록을 제시하고 박현우는 그중 하나를 선택해 "적합" 판정을 확인한 뒤 구매를 진행한다. 규격표를 수동으로 대조하던 과정이 판정 한 번으로 대체된다.

## 5. 범위 외 (D4·D5 폐기 항목)

창문·자연광·태양광 시뮬레이션, 문 위치, 바닥 재질, 방 전체 설계, 책상 사진 촬영 모델링, AR, 공동 편집, 정밀 조도(룩스), 구독형 BM.

> **"사용자 에셋 업로드"는 2026-07-23 이 목록에서 빠졌다** — D20으로 MVP 범위에 편입됐다(REQ-COM-09~11). **2026-08-08 D30으로 다시 범위 밖이 됐다** — REQ-COM-09는 미구현, REQ-COM-10·11은 폐기(아래 폐기 이력). 단 **책상(`spec_type = DESK`) 업로드는 계속 범위 외**다: 절차 생성(D18)이라 에셋 자체가 없고, 사용자 책상은 REQ-ENV-05 직접 입력 규격이 덮는다.

### 폐기 이력

아래 ID는 MVP 범위에서 빠졌다. **ID는 재사용하지 않는다** — 다른 문서·이슈가 계속 참조한다.

- **`REQ-SIM-20` GLB 오브젝트 배치** (2026-08-03 폐기, 승인 박동규) — 어드민 검수 카탈로그(`REQ-SIM-01`)로 흡수. 규격 DB 미등록이라 호환성 판정에 들어가지 못하고 `productId`가 없어 저장도 안 되는 임시 경로였다. 실 에셋은 `GET /products`의 S3 에셋을 `REQ-SIM-01` 경로로 배치한다.
- **`REQ-REC-07` 장바구니** (2026-08-08 폐기, 승인 박동규) — 2026-08-02 프론트 화면 철거(`/cart` 라우트·`CartView`·`AddToCartButton` 삭제). 백엔드 API와 `cart_item` 테이블은 남아 있으나 사용자에게 도달하는 경로가 없다.
- **`REQ-COM-10` 내 업로드 관리 · `REQ-COM-11` 자작 제품 라이브러리 노출** (2026-08-08 폐기, 승인 박동규) — 사용자 에셋 업로드를 MVP에서 열지 않기로 확정(D30). 업로드가 없으면 관리할 것도 공개할 것도 없다.

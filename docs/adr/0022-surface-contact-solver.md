# 0022. 표면 접촉 솔버 — 거치 휴리스틱·박스 스태킹 대체

상태: **대체됨** (0023 — 2026-08-04). 결정 1·2·4, 결정 6의 lift·tilt, 결정 7의 꾹 누르기 폐기, 결정 8이 뒤집혔다 — 자세는 엔진이 아니라 사용자가 정하고 저장한다. 결정 3(게이트 없음)·5(결합 층 무변경)·물리엔진 부결·링 기즈모는 그대로 유효하다. 원래 확정: 2026-08-03, 승인 박동규 — 그릴링 세션

## 맥락

- 거치(D22 ②층)의 안착 계산이 `frontend/src/three/core/cradle.ts` 휴리스틱이다 — "footprint 그리드 하향 레이의 **최저 히트 = 홈**, 최저→최고 벡터 = 기울기". 스탠드 형태(낮은 받침 + 높은 등받이)를 가정한 규칙이라 가정을 벗어나면 각도·위치가 틀린다. 2026-08-02~03 세 차례 시각 반려·수정(등받이 오인 → `seatLiftY` → `seatContactAnchor` x·y·z 고정 + yaw 덮어쓰기) 후에도 아이패드↔스탠드 각도·위치 오답이 남았다.
- 스태킹(매트·라이저)은 별도 경로다 — `core/snap.ts` `supportTopY`가 **규격 박스 상단**(`center.y + heightMm/2`)을 지지면으로 쓴다. 같은 "얹기" 문제를 두 방식으로 풀고 있다.
- 사용자 요구는 "표면을 타고 흐르듯 물리처럼 올려놓기". 단 저장 스키마(`ItemSnapshot`)는 위치 x/y/z + **yaw 하나**만 담고(pitch·roll·쿼터니언 없음) ERD는 동결이다 — 안착 자세를 저장할 자리가 없다.

## 결정

1. **접촉 솔버 도입.** 아이템 밑면 vs 아래 아이템의 실표면(메쉬)에서 **관입 없는 안착 자세(위치 + 기울기)를 기하로 계산**한다. 드래그 중 매 프레임 반영(커서를 따라 표면 위를 흐르고, 홈에 스르륵 앉는다), 드롭·로드 시 동일 솔버 재실행.
2. **결정성 계약.** 솔버는 (아이템 스펙·메쉬, 씬 아이템들, x, z, yaw)의 **순수 함수**다. 저장은 현행 x/z/yaw 그대로, 안착 자세는 로드 때 재계산 — 같은 입력이면 같은 포즈. ERD 동결 유지.
3. **게이트 없음.** `CRADLE_ACCEPTS` 카테고리 표·`stackable` 지지 게이트 폐기 — **아래 표면이 있으면 앉는다.** 이상한 배치는 기존 소프트 블록(충돌 빨강 + 저장 게이트)이 피드백한다. 규격 박스 XZ 겹침에 의한 후보 추리기는 성능 게이트로만 존치(판정 아님).
4. **스태킹 경로 통일.** `supportTopY` 박스 스태킹도 솔버로 흡수 — 같은 문제는 같은 방식으로. 매트·라이저는 상면이 평평해 결과 동일.
5. **결합(mount) 층 무변경.** 모니터↔암·암↔책상의 규격 판정·엣지락·VESA 자석은 그대로다(D22 ①층).
6. **수동 축 재편.** lift(들어올림) 삭제 — 존재 이유(거치 부착 흉내)가 솔버로 소멸. tilt는 **솔버 자세 위의 보정 오프셋**으로 존치(세션 한정, 솔버 어색함 대비 보험). yaw 유지 — 유일하게 저장되는 자세.
7. **회전은 직접 조작으로.** 아이템 발밑 회전 링 기즈모(드래그 = 실시간 회전, 45° 배수 자석 스냅) + R 키 45° 회전(라이브러리 드래그 중 포함). 꾹 누르기 버튼(초당 120°) 폐기. 관절 기즈모의 기존 우선순위 규칙(기즈모 히트 우선, ADR-0002)에 링을 후보로 추가.
8. **부동 선택 툴바(`SelectionToolbar`) 전면 폐기.** 아이템을 따라다니는 컨트롤 구조가 원인이었다(높이 조절 시 패널·마우스 동반 상승 등). 정밀값(yaw°·tilt°)·복제·삭제·해제는 우측 고정 `SelectedItemPanel`로 이동. `selectionAnchor` 프레임별 투영 브리지 소멸.

## 대안과 버린 이유

- **물리엔진(rapier·cannon 등)**: 타임스텝·부동소수·플랫폼별로 결과가 갈려 **비결정적** → 안착 자세 저장 필요 → ERD 언락 + 백엔드 컬럼·DTO·재생성. D22 "물리엔진 금지"(저장 재현성·실측 mm 결정론)가 그대로 유효하고, pixel-bound 씬(postfx 81%, dpr 2에서 프레임 98%가 120Hz 예산 초과)에 상시 시뮬 스텝 예산도 없다. 미끄러짐(중력 동역학)도 같은 이유로 부결 — 놓은 자리에 안 놓이는 것은 배치 도구에서 통제 상실이다.
- **휴리스틱 4차 수정**: 형태 가정이 원인이라 수정으로 못 고친다 — 3회 반려가 실측 근거.
- **거치 삭제 + stackable 승격(박스 얹기)**: 아이패드가 스탠드 위에 눕는다 — 표면 정확도의 후퇴.
- **게이트 유지(stackable 확장·기하 휴리스틱 게이트)**: accepts 표는 코드 주석 스스로 "카테고리 마스터에 컬럼이 없어 코드에 둔 임시 표"라 자백한 부채고, 숨은 기하 게이트는 "왜 안 올라가?"를 디버깅 불가로 만든다. 소프트 블록 철학(자유 이동 + 피드백만)과도 게이트 없음이 일치.

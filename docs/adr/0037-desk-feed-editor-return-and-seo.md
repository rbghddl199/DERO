# ADR-0037. 데스크피드 에디터 회귀와 SEO 렌더링 — 마크다운 본문·공개 SSR·sitemap

## 상태

**확정** — 2026-08-11, 승인 박동규. [ADR-0036](0036-desk-feed-instagram-rollback.md) **결정
1(인스타형 콘텐츠 모델)을 대체**한다 — 0036 결정 2(V13)는 이미 적용된 마이그레이션 역사로
유효하고, 결정 3(배치 사전등록 피커)·결정 4(작업실 게시 입구)도 그대로 유효.
[ADR-0034](0034-desk-feed-post-parity.md) 결정 1·3의 방향(마크다운 본문·아티클 뷰·에디터)을
재확립하되, `is_primary`는 부활하지 않는다(결정 1 참조). [ADR-0033](0033-desk-feed-dedicated-domain.md)의
전용 도메인·배치 단일 FK·양방향은 계속 유효. 기획급 근거는 `docs/CONTEXT.md` D34, 스키마
정본은 `docs/context/erd.md` `desk_feed` 절.

> **개정 (2026-08-11, DERO-613, 승인 박동규)** — 본문 인라인 이미지 상한이 **10장 → 30장**이다.
> 아래 결정 1의 "1~10장"은 결정 당시의 기록이므로 그대로 두고, 현행 값은 이 줄이 정본이다(최소 1장
> 게이트·순서 정본·대표 파생은 전부 불변). 상한은 WAS 강제 조건이라 스키마·마이그레이션 변화가 없다 —
> `DeskFeedService.MAX_IMAGES`·`DESK_FEED_MAX_IMAGES` 두 상수와 `CommunityErrorCode` 문구가 실제 경계다.

## 맥락

D33(ADR-0036)으로 인스타형 회귀를 배포한 당일, 사업 전제가 명시됐다: **이 프로젝트의 사활은
SEO다.** 검색 유입은 크롤러가 읽을 텍스트 총량에 비례하는데, 인스타형(사진 스택 + plain text
선택 본문)은 텍스트를 구조적으로 억제한다. 0036의 관찰 — "사진을 찍어 올리는 사람에게 본문 어디에
이 사진을 박을지는 결정할 이유가 없는 선택" — 은 여전히 참이지만, 그 관찰은 작성 편의의 문제이고
SEO는 생존의 문제다. 우선순위가 갈리면 생존이 이긴다.

실측(2026-08-11)으로 확인된 SEO 현주소:

- 데스크피드·커뮤니티 상세는 **클라이언트 렌더 + 고정 `metadata`**다 — 좋아요 여부·본인 판정이
  세션에 딸려 있어 서버 조회를 통째로 포기했던 것. 크롤러에게 본문은 보이지 않는다.
- `sitemap.ts`·`robots.ts`가 없다. `generateMetadata`는 제품·컬렉션 등 4곳뿐.
- 에픽 570(ADR-0035)은 이미지 레이어(안정 URL·webp)만 해결했다. 텍스트 레이어는 미착수.

즉 에디터만 되살리면 목적 미달이다 — **크롤러가 본문을 읽는 것까지가 이 결정의 완료 조건**이다.

## 결정

### 1. 콘텐츠 모델 — 마크다운 본문이 유일한 정본

- `desk_feed.content`는 **마크다운 본문·NOT NULL**로 전환한다. 인라인 이미지 `![alt](key)`
  1~10장(최소 1장 게이트 유지), **본문 안 위치가 이미지 순서의 유일한 정본**이다.
- `desk_feed_image`는 `display_order`를 폐기하고 **`is_primary`도 부활하지 않는다** — 순수
  소속 레지스트리(id·desk_feed_id·image_key)다. 복합 유니크가 사라지므로 FK 단독 인덱스
  `idx_desk_feed_image_desk_feed_id`를 복원한다.
- **목록 대표 이미지는 본문 첫 이미지에서 파생**한다(별도 컬럼·선택 UI 없음 — 대표를 바꾸려면
  본문에서 이미지 순서를 바꾼다). 목록 API는 대표 키와 `imageCount`(레지스트리 카운트)를 내려준다.
- `PUT imageKeys` 전체 교체는 폐기하고 0034 원형(`00b4a6a1` 트리)의 이미지 등록/삭제
  엔드포인트로 되돌린다(단 `isPrimary` 파라미터 없이). presign 2단계·webp 강제(ADR-0035)는 현행 유지.
- `title`(NOT NULL)·태그 ≤5·`desk_feed_product`(≤10)·배치 피커는 전부 현행 유지.

### 2. 에디터 — `00b4a6a1` 부활 + 드래그 앤 드롭

- 작성/수정 폼은 커뮤니티 `PostRichEditor`(Tiptap) 재사용 — `00b4a6a1` 트리의 데스크피드
  구현(아티클 뷰 `PostContent` 포함)을 부활시킨다(2026-08-11 박동규 승인 — 폐기 코드 복원 규칙 충족).
- **신규**: 본문 인라인 **드래그 앤 드롭** 이미지 삽입(드롭 위치에 삽입) + **클립보드
  붙여넣기**(⌘V 스크린샷). 둘 다 기존 presign 업로드 경로를 태운다.

### 3. 마이그레이션 — V12·V13 불변, V14가 역변환

- 적용된 V12·V13은 불변(체크섬 — ADR-0026 결정 5-1). **V14**가 그 위에서 변환한다.
- 기존 행(전부 사용자 작성분 — 이관본 4건은 삭제 완료): `content` = 기존 plain text 본문 뒤에
  `desk_feed_image`를 `display_order` 순으로 `![](key)`로 이어 붙인다(V13의 역방향, V12에 참고
  로직 존재). 본문이 NULL이면 이미지 마크다운만으로 채운다 — 최소 1장 게이트 덕에 결과는 항상
  비어 있지 않으므로 그 다음 `NOT NULL` 제약을 건다. 마지막으로 `display_order`를 드랍한다.
- 스키마와 화면이 모순되는 중간 상태를 만들지 않도록 **V14와 FE/BE 코드는 같은 배포로 나간다**
  (V12·V13 때와 같은 판단).

### 4. 읽기·SEO — 공개 SSR이 완료 조건

- `GET /desk-feeds`(목록·상세)를 **비로그인 공개**로 전환한다. 좋아요 여부·본인 글 판정은
  별도 클라이언트 조회로 분리한다(세션 딸린 값만 아일랜드).
- 상세는 **서버 컴포넌트가 공개 본문을 SSR**한 아티클 페이지다(제목 `<h1>` + 마크다운 렌더 +
  인라인 이미지). 좋아요 버튼·수정/삭제 메뉴만 클라이언트 아일랜드.
- **`generateMetadata`**(글 제목·본문 발췌) + **schema.org `Article` JSON-LD**를 붙인다.
- **`sitemap.ts`·`robots.ts`를 신설**한다(피드·커뮤니티 글 URL 포함, 관리자·dev 라우트 제외 유지).
- **커뮤니티 post 상세도 같은 패턴을 동시 적용**한다 — 같은 클라 렌더·고정 metadata 구조라
  한 번 잡은 분리 패턴이 그대로 이식된다.
- URL은 `/desk-feed/{id}` 현행 유지(슬러그 없음).

### 5. 목록 화면 — 카드 + 사진 수 뱃지 + 라이트박스

- 카드 = 대표 이미지(본문 첫 장) + 제목 + 본문 발췌. 우상단에 **사진 수 뱃지**(겹친 사진
  아이콘 + N — `imageCount`).
- **뱃지 클릭 → 사진만 넘겨보는 라이트박스 오버레이**(상세 이동 없이 그 자리에서). 카드 본체
  클릭은 현행대로 상세 이동.

## 대안과 버린 이유

- **인스타형과 장문형 공존(듀얼 타입)**: 스키마·피드 UI·작성 폼이 두 벌이 된다. 요청 없는
  flexibility이고, SEO 논리상 텍스트 없는 타입을 남길 이유가 없다.
- **plain text 유지 + SEO 렌더링만**: SSR을 해도 읽힐 텍스트 자체가 없다. 목적 미달.
- **본문을 마크다운으로 두고 에디터만 감추기(0036이 부결한 안의 역방향 재검토)**: 이번엔
  저장·화면을 **둘 다** 마크다운으로 정렬하므로 0036의 "형식은 저장이 정한다" 원칙과 일치한다.
- **`is_primary` 부활(0034 원형 그대로)**: 대표는 본문 첫 이미지로 파생 가능하다. 컬럼 +
  부분 유니크 + 대표 선택 UI가 통으로 불필요해진다.
- **슬러그 URL(`/feed/{id}-{slug}`)**: 한글 제목은 인코딩되면 가독 이득이 없고, SEO 본질은
  본문·메타태그다.
- **임시저장(draft)**: 첫 버전 범위 아님. 필요 신호가 반복되면 그때.
- **스크롤리텔링 연출(패럴랙스 등)**: "스크롤로 스토리"의 답은 일반 아티클 페이지다. 연출은
  크롤러 가독성을 해치고 비용만 크다.
- **호버 이미지 순환(뱃지 라이트박스 대신)**: 모바일에서 죽는다.

## 파급

- **이틀 새 세 번째 개정이다.** 0033(사진 우선) → 0034(post 동형) → 0036(인스타형) → 0037.
  정직하게 적는다: 앞선 두 번의 왕복은 화면·작성 편의 관찰의 대립이었고, 이번에 처음으로
  **사업 전제(SEO 생존)**가 명시되며 축이 고정됐다. 이 전제가 유지되는 한 콘텐츠 모델을 다시
  뒤집을 근거는 없다.
- 2026-08-11 오후 롤백 때 코드·문서에 심은 **"되살리지 말 것" 경고가 전부 무효**가 된다 —
  `DeskFeedUploadForm.tsx`·`DeskFeedDetail.tsx` 헤더 주석, `components/desk-feed/CLAUDE.md`.
  부활 작업에 이 경고 제거가 포함된다.
- `desk_feed`와 `post`의 콘텐츠 모양이 다시 수렴한다. 도메인 분리 근거는 콘텐츠 모양이 아니라
  피드 축이므로(ADR-0033 결정 1) 분리 판단은 불변.
- `GLOSSARY.md` "본문" 정의가 plain text에서 마크다운으로 갱신된다.
- 상세·목록의 공개 전환으로 **비로그인 트래픽이 처음으로 콘텐츠 API에 닿는다** — 캐시·부하는
  현 규모에서 문제가 아니나, 공개 응답에서 세션 딸린 필드(liked·mine)를 빼는 계약 변경이 따른다.
- `docs/context/erd.md` `desk_feed`·`desk_feed_image` 절 개정(동결 해제 승인 2026-08-11),
  V14 마이그레이션, `docs/context/api-spec.md` 갱신.

# ADR-0031. 창문 룩 개정 — 포털 셰이더·블라인드·발광 블룸

## 상태

**확정** — 2026-08-09, 승인 박동규. ADR-0030 **결정 8(창밖 평면)·결정 9(커튼)를 대체**한다.
나머지 결정(스키마·구멍·슬롯·태양·`applyRoom`)은 그대로 유효 — 이 ADR은 **보이는 것만** 바꾼다.

## 맥락

07(창밖 풍경)·08(커튼) 구현이 끝나고 박동규 시각 판정에서 **반려**됐다 (2026-08-09).

**첫째, 창문이 창문처럼 안 보인다.** 개구부가 벽 지오메트리의 구멍뿐이라(ADR-0030 결정 5 —
이 판단 자체는 유효) 두께 0의 구멍 가장자리가 그대로 노출된다. 창틀·창턱·유리 같은 마감
요소가 하나도 없다.

**둘째, 창밖이 "붙인 사진"으로 읽힌다.** 원인은 둘이다.

- **UV 고정 단판**: 카메라를 돌려도 그림이 판에 붙어 같이 돌아, 원경이 아니라 벽에 붙은
  포스터로 판독된다. ADR-0030 결정 8이 패럴랙스를 "개구부가 작아 이득이 없다"고 부결했는데,
  실화면 판정이 그 예측을 반증했다.
- **블룸 경로에서 배제**: 창밖 판이 `MeshBasicNodeMaterial`이라 emissive MRT 슬롯에 0을 쓴다.
  이 씬의 "빛 번짐"은 포스트프로세싱 블룸 2단(`postfx.ts:112` 발광 블룸 + `:137` 글레어)이고
  소스가 emissive MRT라, 창밖은 램프처럼 번질 수 있는 경로 자체가 막혀 있었다. 램프가 광원으로
  읽히는 바로 그 메커니즘에서 창문만 빠져 있으니 "바깥의 빛이 안으로 들어오는 느낌"이 없다.

**셋째, 위·바깥 시점에서 판이 통째로 노출된다.** 판이 창 사각형보다 여백 1.2m 크게, 벽 뒤
0.35m 물러나 떠 있어(스침각 대비 여백) 시점이 벽 위로 올라가면 "떠 있는 하늘 광고판"이 보인다.

**넷째, 커튼이 반려됐다** — 레퍼런스(백색 베네시안 블라인드, 슬랫 사이 과노출 블로우아웃)와
방향이 다르다.

## 결정

### 1. 창밖 판은 개구부에 딱 맞는 포털이다 — 셋백·여백 폐지

풍경 판을 **창 사각형 크기 그대로, 벽면과 같은 평면**에 끼운다. 물러남·여백이 사라지므로
위·바깥 시점의 판 노출이 구조적으로 소멸한다 — 밖에서 보면 "창문에 하늘이 비치는 벽"이고,
그것은 실제 건물을 밖에서 본 것과 같아 자연스럽다.

원근은 지오메트리가 아니라 **셰이더**가 만든다: 하늘은 픽셀별 **시선 방향**으로 샘플링해
무한 원거리로 읽히고(스카이박스와 같은 원리), 실루엣 층은 가상 깊이만큼 UV를 시선에 따라
밀어(패럴랙스) 층간 어긋남을 낸다. 판은 여전히 1장, 드로우콜 증가 없음 — ADR-0030 결정 8이
패럴랙스를 부결한 사유(물리 3판·드로우콜 3배)는 이 방식에 적용되지 않는다.

### 2. 창밖·개구부는 emissive MRT를 타고 블룸으로 번진다

창밖 색을 emissive MRT 슬롯에 실어 램프와 **같은 블룸 경로**(`bloom(scenePassEmissive, ...)`)로
번지게 한다. 슬랫 사이·개구부 가장자리가 하얗게 날아가는 과노출 블로우아웃 + 바닥 햇살
웅덩이(기존 태양 세기·범위 재조정)가 "빛이 안으로 들어오는" 인상을 만든다.

**밝기 배율(`DAY_SCALE`) 인상은 금지 유지** — 하늘 전체가 글레어 threshold 50을 넘어 통째로
번진다(`windowNodes.ts:110-111` 경고). 번짐은 배율이 아니라 emissive 슬롯 경유가 정석이다.

**해 원반은 제거한다.** "뿌연 빛무리" 반려 이력이 있는 부품이고, 과노출 그라디언트가 태양
방향을 이미 말해 준다.

### 3. 개구부 마감 메쉬를 신설한다 — 창틀·창턱·밸런스, 백색 고정

둘레 창틀 트림 + 하단 창턱 + 상단 밸런스 박스(블라인드 헤드레일 덮개)를 씬이 짓는다
(드레싱 그룹 소속 — 마감 모듈 권한 밖, ADR-0021 결정 2·ADR-0030 결정 10 경계 유지).
색은 **백색 고정** — 실제 인테리어의 창호 기본값이고, 마감 계열 연동은 벽 마감 룩 재설계
때 값이 생기면 그때 본다. 유리판은 만들지 않는다 — 창밖은 포털이 그리므로 유리판이 더할 것은
반사·틴트뿐인데, 그 값이 재질 비용을 못 갚는다. 돌출은 커튼 전례의 **20mm 캡을 상속**하고 `raycast` 무력화도 같다.

### 4. 커튼 → 베네시안 블라인드 — 고정·정적·백색

위에서 **개구부 높이의 0.45만 내려오고**(아래는 창밖이 그대로 보인다) 슬랫이 반쯤 열린
(빛이 새는 각) **고정 상태 하나**다. 기준은 물리 비율이 아니라 **화면**이다 — 표준 창은 윗변
37%가 HUD 툴바 뒤라 물리 1/3만 내리면 화면에 한 픽셀도 안 나오고, 0.58이면 히어로에서
밑단이 수평선에 걸려 하늘·스카이라인이 0px였다(2026-08-09 실측·2차 조정). 개폐·틸트 UI는 만들지
않는다 — 조절 축은 저장 스키마·UI·BE로 번지는 기획 재개봉이라 범위 밖. 블라인드는 물리상
흔들리지 않으므로 **정적**이고, 커튼의 스웨이 셰이더(`windowNodes.ts` 주름/스웨이)와
`curtain.ts`는 **삭제**한다(선택 축 대비 보존 안 함 — 죽은 코드는 산 코드로 오독된다.
되살릴 일이 생기면 git에 있다). 자동 드레싱이라는 지위는 유지 — 저장 스키마 무변경.

### 5. 소재 — 주야 모두 도시, 세 겹의 거리로 원근을 만든다 (2026-08-09 개정)

주간·야간 모두 **도시**다(개정 전에는 주간이 하늘 + 흐릿한 나무 실루엣이었으나 "낮 배경이
납작하고 마음에 안 든다"로 반려됐다). **시점은 고층이다** — 창밖 지면이 눈높이 **60m 아래**다(레퍼런스: 고층에서 내려다본 도심).
지면이 눈높이 바로 아래면 건물이 전부 수평선 위로 솟아 창을 벽처럼 막는다. 60m 아래로
내리면 옥상이 수평선 아래에 깔려 가까운 동은 낮고 먼 동일수록 수평선으로 쌓여 올라가며,
하늘이 화면 위쪽 절반을 갖는다.

실루엣은 가상 깊이 **360m · 380m · 740m 세 겹**(건물 높이 18.7~80.75m)이고, 앞 층이 뒷 층을
가리는 것 + 멀수록 하늘색에 잠기는 대기 원근 + 층마다 다른 창 격자 크기가 거리를 말한다.
야간에는 층마다 켜진 창이 크기를 달리해 번져 그대로 야경이 된다.

**2026-08-09 값 개정(박동규 프로토타입 판정, `prototype/window-portal-look` 브랜치).** "건물이
2D다" 지적으로 **옥상면 투영·파라펫·동 윤곽선·측면 그늘**이 추가됐다 — 고층 시점이라 옥상이
보여야 상자로 읽힌다. 시점 −76m, 깊이·높이는 위 값, 구름 적고 큰 덩어리(문턱 0.72), 해는
수평선 높이의 은은한 글로우(0.15), DAY_SCALE 8.5 · NIGHT_SCALE 4. 숫자 정본은
`render/windowNodes.ts` 상수다. 프로토타입 대안이었던 작화 텍스처 층은 채택하지 않았다
(결정 1 유지) — 브랜치에 보존.

하늘은 파랑이 남아야 한다 — 주간 배율 20·12는 ACES 어깨에서 흰 판이 됐고 9에서 파랑이
남는다. 구름만 흰색이라 그 대비가 뭉게구름으로 읽힌다. 지면(길)은 이 시점에서는 화면
밖이지만 평면 투영 코드는 유지한다(저층 창을 다시 다룰 때 쓴다).

야간은 어두운 청색 + 층마다 켜진 창 불빛(emissive로 은은히 번짐)이고, 바닥 웅덩이는 야간엔
태양이 꺼지므로 없다(ADR-0030 결정 7의 귀결). 주야 대비는 밝기·불빛이 만든다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| **UV 고정 단판 유지(현행)** | "붙인 사진" 반려의 직접 원인. 시점이 움직여도 그림이 안 움직인다 |
| **실제 다층 판 2~3장** | 효과는 셰이더 패럴랙스와 같은데 판 관리·벽 경계 접힘 처리가 배로 는다. ADR-0030이 부결한 드로우콜 문제도 되돌아온다 |
| **진짜 원경 지오메트리/스카이돔** | 방 밖 물체는 외부 시점 노출 문제를 다시 연다(벽 밖 하늘 판 지적 전례). 과잉 |
| **카메라 위치 기반 판 숨김** | 증상 치료 — 경계에서 팝이 생기고, 밖에서 본 창문이 구멍만 뚫린 벽이 된다 |
| **여백 판 유지 + 각도 페이드** | 노출각 튜닝 지옥. 포털이면 문제 자체가 없다 |
| **`DAY_SCALE` 인상으로 번짐** | 하늘 전체가 글레어 threshold를 넘어 통째로 번진다 — 코드에 경고가 박혀 있는 함정 |
| **볼류메트릭 광선 기둥** | 먼지 낀 창고 룩이 되기 쉽고 레퍼런스에도 없다 |
| **유리판(반사·틴트)** | 창밖은 포털이 그린다. 유리가 더할 반사·틴트는 재질 비용을 못 갚는다 |
| **블라인드 개폐·틸트 조절** | 저장 필드·UI·BE로 번지는 스키마 변경 = 기획 재개봉. 고정 상태로 룩은 완성된다 |
| **커튼/블라인드 선택 축** | 같은 이유로 스키마 변경. 커튼 복원은 git이 담보한다 |
| **커튼 코드 보존(주석·데드 코드)** | 다음 사람이 산 코드로 오독한다 |

## 파급

- **`render/windowNodes.ts` 재작성** — 시선 방향 하늘 샘플링 + 실루엣 패럴랙스 + emissive MRT
  출력 + 해 원반 제거 + 커튼 스웨이 삭제. TSL `@ts-nocheck` 격리 유지
- **`scene/windowView.ts` 포털화** — 셋백·여백·벽 경계 접힘 코드 삭제, 창 rect 1장.
  `MeshBasicNodeMaterial` → emissive MRT에 실리는 재질로 교체
- **`scene/curtain.ts` 삭제** → `scene/blind.ts` 신설(슬랫·헤드레일), 창틀·창턱·밸런스 메쉬 신설
- **스키마·API·BE 무변경** — 드레싱은 저장 대상이 아니다(`hasWindow` + mm 4값 그대로)
- **e2e·vitest** — 20mm 캡·raycast 무력화 단언은 블라인드·마감 메쉬가 상속. 셔터 스크린샷
  (`window-view-DAY/NIGHT.png`)은 계속 찍는다
- **시각 판정은 박동규** — 주·야 창밖 + 블라인드 + 바닥 웅덩이, 자동 게이트로 대체하지 않는다

# ADR-0030. 방 표면은 벽면별로 고르고, 시간대와 창문을 갖는다

## 상태

**확정** — 2026-08-08, 승인 박동규. **결정 8·9는 ADR-0031이 대체** (2026-08-09 — 창밖 포털
셰이더·블라인드·발광 블룸). ADR-0021 **결정 3·4·5를 대체**하고 결정 2의 벽 지오메트리
소유권 한 줄을 개정한다. ADR-0021의 결정 1(테마는 코드 모듈)·2(권한 경계)·6(통째 dispose)은
그대로 유효하다 — 룩의 정본이 데이터가 아니라 코드라는 판단은 뒤집히지 않았다.

기획급 결정은 `docs/CONTEXT.md` **D31**이 정본이다(D4·D5의 창문·자연광·바닥 폐기 부분 취소).

## 맥락

ADR-0021이 방 표면을 `theme_key` **한 축**으로 통일한 지 5일이 지났고, 그 결정의 전제 두 개가
동시에 깨졌다.

**첫째, 축 하나가 실제 요구를 못 담는다.** 사용자가 원하는 것은 "벽 3면이 한 벌로 바뀌는 것"이 아니라
**면마다 다른 마감**이고, 거기에 창문 위치까지 고른다. 테마 키로 담으려면 조합마다 테마를 하나씩
만들어야 한다 — 계열 5종 × 3면이면 125개다.

**둘째, 무드 축에 시간대가 없다.** D5가 조명을 무드 시뮬레이션 필수로 승격했고 `is_room_light_on`이
이미 방 전체를 어둡게 만든다(`roomRig.ts:58-66` — 세기 0 + `environmentIntensity` 10→1.0 +
`backgroundIntensity` 20→3.0). 즉 "밤"의 절반이 이미 구현돼 있는데 창밖도 햇살도 없어서 그것이
"불 끈 낮"으로만 읽힌다.

동시에 **D4가 창문·자연광·바닥 재질을 명시적으로 폐기**해 뒀고 D5가 "자연광·시간대별 빛 변화 폐기
유지"를 적어 뒀다. 그런데 ADR-0021은 이미 그 중 "바닥 재질·방 분위기"를 뒤집은 상태로 굴러왔다 —
`docs/CONTEXT.md`는 "테마"도 ADR-0021도 한 번도 언급하지 않는다. 이 ADR은 그 조용한 모순까지 같이
닫는다(D31).

기존 제약 중 이 결정 위에 그대로 걸려 있는 것들:

| 제약 | 근거 |
|---|---|
| **광원 집합을 런타임에 바꾸면 실기 WebGPU가 1.2~1.9초 멈춘다** | `lighting-map.md` 실측. `scene/lightSlots.ts` 머리 주석이 못박음 — 개수·`castShadow` 플래그가 곧 `LightsNode` 셰이더 해시이고 `visible`도 만지면 안 된다(빈 슬롯은 `power = 0`) |
| 그림자 캐스터는 총 3칸 | ADR-0014 — 램프 2칸 상수 + room key 1칸 상시 점유 |
| 벽은 배경이 아니라 **기능 부품** | `scene.ts`가 벽 메쉬를 raycast해 벽걸이 배치점을 잡고, 벽 좌표를 충돌 클램프 평면으로 쓴다. 전면 벽 z는 책상 깊이를 추종한다 |
| 벽 3면은 이미 **독립 재질 인스턴스**다 | `scene.ts:952-960` `applyTheme`가 `materials()`를 면 수만큼 따로 부른다("사이드별 액센트가 가능해야 한다") — 벽면별 마감의 배관이 이미 깔려 있다 |
| TSL은 `nodes.ts` + `@ts-nocheck` 격리 필수 | 일반 파일에 쓰면 tsc 인퍼런스가 ~70GB OOM으로 머신을 죽인 전례(2026-07-17) |
| JSONB는 이 스키마가 세 번 기각했다 | `asset.emitter_manifest` JSONB → 정규 컬럼 9개(`erd.md:688`) · `placed_item` 좌표를 JSON에 안 둠(`:1017`) · `pitch_deg`를 `joint_values`에 얹는 우회 부결(`:1487`) |

## 결정

### 1. 축은 벽면별 마감이고, 프리셋은 저장되지 않는다

좌·전면·우 3면이 각자 **`{재질 계열, 변형, 표시 여부, 창문}`**을 갖고 바닥은 **`{계열, 변형}`**
한 벌이다. `placement.theme_key`는 폐기한다.

방 프리셋은 UI에 남지만 **저장되지 않는다** — 클릭하면 3면 값에 써넣는 **프리필 버튼**이고 저장되는
정본은 벽면별 값 하나다. ADR-0021 결정 4가 축 둘을 기각한 사유("재로드 때 누가 이기는지를 매번
정해야 하고 조합 폭발로 QA가 불가능하다")는 **프리셋이 값을 갖지 않으므로 발생하지 않는다.**
프리셋이 필요한 이유는 원클릭으로 좋은 답이 나와야 하기 때문이다 — 레퍼런스 4/4가 조합의 결과였고,
빈 캔버스에서 3면 × 계열 × 변형을 직접 맞출 수 있는 사용자는 소수다.

v1 프리셋 6개: 기존 4종을 이관한 `neutral`·`oak-warm`·`white-clean`·`dark-studio` + 창문 있는
`morning-window`·`night-city`.

### 2. 색은 계열이 소유한다 — 자유 hex는 여전히 금지

| 계열 | 변형 | 벽 장식 |
|---|---|---|
| `PAINT` | 프리셋 12색 (무채·웜그레이·세이지·차콜 …) | 걸레받이 |
| `WOOD_SLAT` | 오크 / 월넛 / 애쉬 | 슬랫 + 배킹(14mm) |
| `BRICK` | 적 / 백 / 회 | 걸레받이 |
| `MARBLE` | 화이트 / 블랙 | 몰딩 |
| `CONCRETE` | 라이트 / 다크 | 없음 |

바닥 계열 3종: `WOOD`(오크/월넛/라이트오크) · `TILE`(화이트/그레이) · `CARPET`(그레이/베이지).

**2026-08-03에 폐기한 "벽지 색·바닥 색 피커"를 되살리는 것이 아니다.** 그 폐기 사유는 자유 hex가
절차 룩과 양립 불가라는 것이었다(우드 슬랫에 세이지 그린을 먹이면 나무가 초록이 된다). 계열이 자기
변형 목록을 정의하면 **그 조합이 구조적으로 만들어지지 않는다** — 되살린 것이 아니라 그 사유를
구조로 못박은 것이다. `<input type="color">`는 복원하지 않는다.

### 3. 저장은 `placement_wall` 자식 테이블이다 — `is_wall_*_on`도 여기로 옮긴다

```sql
-- V8__placement_wall_finish.sql (확장), V9(축소)에서 옛 컬럼 DROP
CREATE SEQUENCE placement_wall_id_seq INCREMENT BY 50;
CREATE TABLE placement_wall (
  id                 BIGINT      NOT NULL DEFAULT nextval('placement_wall_id_seq'),
  placement_id       BIGINT      NOT NULL,
  wall_side          VARCHAR(10) NOT NULL,  -- LEFT / FRONT / RIGHT
  is_on              BOOLEAN     NOT NULL DEFAULT true,
  material           VARCHAR(30) NOT NULL DEFAULT 'PAINT',
  variant            VARCHAR(30) NOT NULL,
  has_window         BOOLEAN     NOT NULL DEFAULT false,
  window_center_x_mm INT,        -- has_window = false면 NULL
  window_center_y_mm INT,
  window_width_mm    INT,
  window_height_mm   INT
);
-- pk_placement_wall · fk_placement_wall_placement · uq_placement_wall_placement_id_wall_side
ALTER TABLE placement ADD COLUMN floor_material VARCHAR(30) NOT NULL DEFAULT 'WOOD';
ALTER TABLE placement ADD COLUMN floor_variant  VARCHAR(30) NOT NULL DEFAULT 'OAK';
ALTER TABLE placement ADD COLUMN time_of_day    VARCHAR(10) NOT NULL DEFAULT 'DAY';
```

**바닥은 면이 하나라 테이블을 만들지 않는다** — 3면이 반복되는 벽과 달리 행이 하나뿐이면 조인만 늘고
얻는 게 없다.

**`is_wall_left_on`·`is_wall_front_on`·`is_wall_right_on` 3컬럼을 `placement_wall.is_on`으로
옮긴다.** 벽 데이터가 `placement` 컬럼과 자식 테이블 두 곳에 갈리면 "이 벽 상태가 뭐냐"를 볼 때마다
어디를 보는지 갈린다 — 이 스키마가 반복적으로 기각한 패턴이 정확히 그것이다(`material_skin` 테이블
폐기 · `emitter_manifest` 이동 · `theme` 마스터 테이블 기각, 셋 다 정본 이중화가 사유).

`time_of_day`는 **GLOSSARY §2-3 표준 단어에 이미 있고** 값 공간도 이미 정의돼 있다(`DAY`/`NIGHT`,
`generated_image.time_of_day`가 쓴다). 전역 규칙 준수: `CHECK` 없음 · nullable boolean 없음 ·
enum은 `VARCHAR` + UPPER_SNAKE · PK는 명시 시퀀스 `INCREMENT BY 50`.

**WAS는 `material`·`variant`로 아무 판정도 하지 않는다** — 형식 검증까지다. 계열을 늘릴 때 백엔드
배포가 붙으면 결정 1(코드 갈아끼우기)이 무뎌진다는 ADR-0021 결정 3의 판단을 그대로 잇는다. 미상
값은 에러가 아니라 `PAINT` 기본 변형 폴백이다.

### 4. 시간대는 방 조명과 연동하되 병합하지 않는다

`time_of_day`(DAY/NIGHT)와 `is_room_light_on`은 **별개 값 두 개**다. 시간대를 바꾸면 방 조명이
**기본값으로 따라 움직이고**(DAY→on, NIGHT→off) 사용자가 그 뒤 따로 토글할 수 있다.

병합하면 조합 둘이 영구히 사라진다 — **자연광만 드는 아침**(창문을 넣는 이유의 절반)과 **천장등 켠
밤**이다. 컬럼 하나로 조합 4개가 전부 유의미하고, UI는 컨트롤 2개지만 원하는 무드는 클릭 한 번에
나온다(연동이 그 일을 한다).

### 5. 창문은 벽 지오메트리의 진짜 구멍이다

벽 메쉬를 `PlaneGeometry`가 아니라 `Shape` + `holes`로 만든다. **raycast가 구멍을 통과하므로
벽걸이 배치가 자동으로 창문을 피한다 — 판정 코드가 한 줄도 늘지 않는다.** 충돌 클램프는 좌표(숫자)를
쓰므로 무영향이고, 지오메트리는 셰이더 해시가 아니라 재빌드도 없다.

알파 마스크 개구부는 부결이다 — 투명 재질이 되어 정렬·그림자가 딸려오고, 벽걸이 회피를 여전히 코드로
짜야 한다. "창문 사각형을 배치 금지 구역으로 `resolveWallPose`에 넣는" 안도 같은 이유로 부결이다.

### 6. 창문 위치는 유한 슬롯이고, 저장은 mm다

UI는 **가로 3슬롯(좌/중/우) × 크기 2종**(스탠다드 1200×1400 · 와이드 1800×1400)이고 **창턱 높이는
900mm 고정**이다. 연속 자유 배치는 드래그마다 벽 지오메트리 재생성 + 벽걸이 아이템 전량 resnap을
유발하고, 창턱을 자유롭게 열면 창문이 책상을 관통하는 조합이 생긴다.

**저장은 슬롯 이름이 아니라 `_mm` 정수다.** 나중에 자유 배치로 열 때 스키마 변경이 0이다.

### 7. 햇살은 광원을 만들지 않는다 — `roomRig` key를 태양으로 재정의한다

`roomRig.ts:20-31`의 key는 이미 `DirectionalLight(0xffffff, 60)` + `castShadow` + ortho ±2.2,
즉 **태양과 같은 물건**이다. 방향·색만 주 창문에서 계산한다 — 둘 다 유니폼이라 셰이더 재빌드가 없고
그림자 칸도 늘지 않는다(총 3칸 유지).

**창문은 벽면당 0~1개(최대 3개)지만 햇살은 방에 1개다.** 태양은 하나이고, 창문마다 광원을 두면
광원 집합이 배치마다 달라져 재빌드와 그림자 캡에 정면으로 걸린다. 주 창문은 **자동 우선순위 전면 >
좌 > 우**이고 꺼진 벽은 제외한다(사용자가 주 창문을 고르는 UI는 만들지 않는다 — 결정을 하나 줄인다).
창문이 없거나 해당 벽이 다 꺼진 방은 `intensity = 0`이고 **광원은 그대로 있다**.

`createRoomRig(scene, { sun })`으로 갈라 **관리자 발광 프리뷰(`emitterPreview.ts`)는 `fixed`**를
쓴다 — 같은 리그를 공유하므로 검수 화면이 창문 방향을 따라가면 안 된다.

### 8. 창밖은 평면 한 장 + 절차 셰이더다

창 개구부 뒤에 평면 1장을 두고 하늘 그라디언트·해/달 원반·별·구름 노이즈·건물 SDF 실루엣·지평선을
**한 개의 TSL 셰이더**로 계산한다. 애니메이션(구름 스크롤·별 반짝임)은 **유니폼 시간 하나**다 —
재빌드가 없고 비용이 그 평면 픽셀에만 든다.

`scene.background`(studio-cyc 그라디언트)는 **손대지 않는다** — 교체하면 벽 밖 여백까지 하늘이 되고
W11 심 처리가 깨진다. 레이어 패럴랙스·큐브맵은 창 개구부가 화면에서 작아 이득이 없어 부결.

**창밖에 GLB 소품을 쓰지 않는다** — 배경 화분과 사용자가 배치한 제품이 화면에서 구분되지 않으면
"사기 전 검증" 신뢰가 깨진다(ADR-0021이 테마 GLB를 기각한 사유 (b) 유지).

### 9. 커튼은 20mm 안에서 흔들린다

`MAX_RELIEF_PROTRUSION_M`(20mm) 캡을 지키는 **얇은 패널**이고, 흔들림은 정점 변위 없이 노멀·UV
웨이브(`update(dt)`)로 낸다. 실제 커튼 주름은 100~150mm이지만 캡을 열면 벽걸이 관통이 눈에 띄고,
"창문 사각형만 캡 예외 + 그 구역 배치 금지"는 판정 코드를 늘리면서 ADR-0021이 이산 벽 장식을 기각한
사유("관통은 사기 전 검증이라는 제품 목적을 직접 깎는다")를 정면으로 뚫는다.

### 10. 씬의 창구는 `applyRoom(config)`다 — 벽 지오메트리 소유권은 씬에 남는다

`applyTheme(key)`를 **`applyRoom(config)`**로 넓힌다. 벽면 3벌 + 바닥 + 창문 + 시간대를 받아
씬이 벽 지오메트리를 재생성하고 재질을 교체한다.

ADR-0021 결정 2의 **금지 목록은 그대로다** — 마감 모듈은 광원을 만들 수 없고, 벽·바닥의 위치·크기·
`visible`을 만질 수 없고, 이산 벽 장식을 놓을 수 없고, 자유 hex tint를 쓸 수 없다. 개정되는 것은
"창문 개구부는 마감이 아니라 **씬**이 뚫는다"는 한 줄이다. 부조 돌출 ≤20mm와 decor `raycast = () => {}`
가드도 유지한다.

전환은 ADR-0021 결정 6대로 **통째 dispose·캐시 없음**이다. 다만 벽면마다 계열이 다르면 NodeMaterial
셰이더 **프로그램이 최대 3벌** 동시에 존재한다(지금은 인스턴스 3개·프로그램 1개) — 첫 전환 스톨을
측정해 300ms를 넘으면 그때 프리워밍을 넣는다(미리 넣지 않는다).

### 11. `neutral` 기본과 e2e 중립 가드를 검수 화면으로 옮긴다

`e2e/lighting.spec.ts:63-64`의 기본 상태 벽 R/B 0.9~1.12 가드가 지키던 것은 "제품 색 판단 왜곡
방지"다. 그 판단이 실제로 필요한 화면은 시뮬레이터가 아니라 **제품 검수·발광 프리뷰**이고, 결정 7의
`sun: 'fixed'`가 이미 그 화면을 중립으로 고정한다 — 중립 어서션을 그쪽으로 이전한다.

시뮬레이터 e2e는 **무드 회귀**로 바꾼다: DAY가 NIGHT보다 밝다 · NIGHT가 칠흑이 아니다(ambient
floor) · 창문 있는 벽에 벽걸이가 창문 자리에 안 붙는다.

`environment.ts`의 색 캐스트 0 HDRI는 **그대로 쓴다** — IBL을 색으로 물들이면 제품 재질 판단이
계열과 무관하게 왜곡되고, 온기는 마감 재질의 웜톤과 햇살 색이 낸다.

### 12. 기존 `theme_key`는 결정론적 매핑으로 이관하고, 창문은 넣지 않는다

| 기존 키 | 좌 | 전면 | 우 | 바닥 |
|---|---|---|---|---|
| `neutral` | PAINT 무채 | PAINT 무채 | PAINT 무채 | WOOD 오크 |
| `oak-warm` | WOOD_SLAT 오크 | WOOD_SLAT 오크 | PAINT 웜그레이 | WOOD 오크 |
| `white-clean` | PAINT 화이트 | WOOD_SLAT 애쉬 | PAINT 화이트 | WOOD 라이트오크 |
| `dark-studio` | PAINT 차콜 | PAINT 차콜 | PAINT 차콜 | WOOD 월넛 |

`has_window`는 **전부 `false`**, `time_of_day`는 전부 `DAY`, `is_on`은 옛 boolean 3컬럼을 그대로
옮긴다. **마감은 재로드 시 같게 열린다** — 창문 있는 기본값은 신규 배치에만 적용된다.

**단, 조명은 같지 않다**(2026-08-09 문장 정정, DERO-514). 옛 배치는 창문이 없으므로 결정 7에
따라 **주간에도 태양 세기가 0**이다 — 이 표가 정하는 것은 마감·바닥의 무회귀이고, 빛까지 같기를
약속하지 않는다. 창문 없는 방이 어두운 것은 의도된 결과다(창문을 넣으면 햇살이 돌아온다).

마이그레이션은 ADR-0026의 **확장/축소**를 따르고 배포가 **셋**이다(2026-08-09 실행 시 확정,
DERO-514):

1. **V8** — 테이블·컬럼 신설 + 이관 백필(01, 배포 완료).
2. **V9 + 코드**(`V9__placement_wall_residual_backfill.sql`) — 벽면 행이 0행인 배치를 같은 표로
   다시 백필하고, 같은 배포에서 코드가 옛 4컬럼을 **읽지 않게** 된다(엔티티·DTO·합성 폴백 제거).
   잔여 백필이 필요한 이유는 V8 이후 blue-green 창에서 옛 WAS가 만든 배치가 0행이고 상세 응답의
   합성 폴백이 그 컬럼을 근거로 삼고 있었기 때문이다.
3. **V10** — 옛 4컬럼 DROP.

**2와 3을 합치면 안 된다.** Flyway는 새 색 컨테이너가 뜰 때 커밋하는데 그 시점 옛 색이 아직
트래픽을 받고 있고, 옛 빌드의 엔티티가 그 컬럼을 SELECT한다 — nginx 스위치 전까지 배치 조회·저장이
통째로 500이다. 축소는 "읽는 코드가 전부 사라진 **뒤**"다. 컬럼이 `NOT NULL DEFAULT`라 2단계의
새 코드가 값을 안 실어도 INSERT는 성립한다.

**프론트에는 이 이관 맵을 두지 않는다**(2026-08-09 결정, DERO-514). 이관은 SQL이 한 번에
끝내므로 `themeKey`를 읽는 클라이언트 폴백(`resolveRoomPresetKey`)은 쓸 자리가 없다 — 벽면 값을
쓰는 프론트는 V8이 배포된 뒤에야 나가고, 그 시점부터 모든 응답이 `walls[]` 3행을 싣는다. 그래서
그 함수는 지웠다. 프리셋은 프리필 버튼으로만 남는다(결정 1).

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| **테마 키를 계열 조합만큼 늘린다** | 계열 5종 × 3면 = 125개. 칩 그리드가 무의미해지고 프리셋과 조합의 구분이 사라진다 |
| **테마 키 + 벽면별 오버라이드 병존(둘 다 저장)** | ADR-0021 결정 4가 기각한 "재로드 때 누가 이기나"가 그대로 돌아온다. 프리셋을 저장하지 않으면 그 문제가 사라진다 |
| **아침/밤을 `is_room_light_on`에 병합** | "자연광만 드는 아침"과 "천장등 켠 밤"이 영구히 사라진다. 컬럼 하나를 아껴서 유의미한 조합 절반을 버리는 거래다 |
| **시간대를 테마 키 곱집합으로(`oak-warm-night`)** | 키가 2배가 되고, `dark-studio`의 아침이 무엇인지 정의가 없다. 시간대는 마감과 직교한다 |
| **벽면별 값을 `placement` 컬럼 15개로** | 면이 늘거나(뒷벽·천장) 속성이 늘 때마다 컬럼 폭발. nullable INT가 6개 생긴다 |
| **벽면별 값을 JSONB 1컬럼으로** | 이 스키마가 세 번 기각한 선례(`emitter_manifest`·`placed_item` 좌표·`pitch_deg` 우회). 살아남은 JSONB 3종은 전부 키 집합이 가변이고 조회 대상이 아니다 — 벽면은 면이 정확히 3개로 고정이고 속성도 고정이다 |
| **`is_wall_*_on`을 `placement`에 남기고 새 테이블만 추가** | 벽 정본이 두 곳으로 갈린다. 이 스키마가 `material_skin`·`emitter_manifest`·`theme` 마스터에서 세 번 같은 이유로 접은 패턴 |
| **창문을 알파 마스크 개구부로** | 투명 재질이라 정렬·그림자가 딸려오고, 벽걸이 회피를 여전히 판정 코드로 짜야 한다. 진짜 구멍은 raycast가 공짜로 해결한다 |
| **창문 사각형을 벽걸이 배치 금지 구역으로 `resolveWallPose`에 추가** | 결정 5가 코드 0줄로 같은 결과를 낸다 |
| **창문 위치·크기 연속 자유 배치** | 드래그마다 벽 지오메트리 재생성 + 벽걸이 전량 resnap. 창턱 자유는 창문이 책상을 관통하는 조합을 만든다. 저장이 mm라 나중에 열 수 있다 |
| **햇살용 `DirectionalLight`를 새로 만든다** | 광원 집합이 늘어 셰이더 재빌드(1.2~1.9초)와 그림자 캡에 걸린다. `roomRig` key가 이미 같은 물건이다 |
| **창문마다 햇살 1개** | 광원 개수가 배치마다 달라진다 = 배치를 열 때마다 재빌드. 태양은 물리적으로도 하나다 |
| **주 창문을 사용자가 고르는 UI** | 결정 하나를 더 만들면서 얻는 것이 없다. 우선순위 자동이면 실제 방과 같게 읽힌다 |
| **`scene.background`를 시간대별 스카이박스로 교체** | 벽 밖 여백까지 하늘이 되어 W11 심 처리가 깨지고, 창문 없는 마감에서도 하늘이 보인다 |
| **창밖을 하늘/구름/건물 3레이어 패럴랙스로** | 창 개구부가 화면에서 작아 시차 이득이 거의 없고 드로우콜만 3배 |
| **창밖 풍경·커튼을 GLB로** | 에셋 파이프라인(검수·presign·admin 등록)에 물리고, 배경 소품과 배치한 제품이 구분되지 않는다(ADR-0021 유지) |
| **커튼 캡(20mm) 예외 허용** | 관통이 눈에 띈다. ADR-0021이 이산 벽 장식과 안전 밴드를 기각한 사유가 그대로 적용된다 |
| **e2e 중립 가드를 그냥 삭제** | 제품 색 판단은 여전히 제품 가치다. 지킬 화면이 시뮬레이터에서 검수로 옮겨간 것이지 없어진 것이 아니다 |
| **`neutral`을 기본으로 유지하고 창문 있는 마감은 선택으로만** | 창문이 기본에 없으면 대부분의 사용자가 그 기능을 못 본다. 무회귀는 기존 저장본에만 필요하고 결정 12가 그것을 보장한다 |

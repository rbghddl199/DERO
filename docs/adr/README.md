# ADR — 아키텍처 결정 기록

기술 결정의 **근거**가 사는 곳. MADR 경량 형식, 한국어. 기획급 결정은 여기가 아니라 `docs/CONTEXT.md` D 시리즈다.

## 규약

- **[ADR-0041](0041-harness-matt-pocock-realign.md)부터 Matt 포맷이다** — frontmatter 상태 + 간결한 본문(1문단 가능), 절 6종을 채우는 의무 없음. 아래 절 규약과 상태 3값은 **0001–0040(legacy)에만** 적용된다.
- **관련 ADR은 frontmatter `relates-to:`로 잇는다** (0041+). 무엇을 잇는지까지 한 줄로 적는다 — `relates-to: ADR-0041 (…이 건을 별건으로 넘겼다)`. 앞선 ADR을 대체하면 **그쪽 문서의 상태 줄도 같은 커밋에서 고친다**. 새 ADR을 아래 legacy 표에 등재할 의무는 없다(ADR-0041 결정).
- 파일명은 **`NNNN-kebab-title.md`** — 4자리 0채움(`0001`), 소문자 kebab-case 제목.
- **순번은 재사용하지 않는다.** 폐기된 ADR의 번호도 비워두지 않고 그대로 둔다.
- 절: 제목 / 상태 / 맥락 / 결정 / 대안과 버린 이유 / 파급.
- 상태는 **확정 / 대체됨 / 폐기** 3값. 확정에는 날짜와 승인자를 적는다. 대체됐으면 후속 ADR 번호를, 폐기했으면 사유를 같은 줄에 적는다.
- **기존 ADR을 고쳐 결정을 뒤집지 않는다** — 새 ADR을 쓰고 옛 것의 상태를 `대체됨`으로 바꾼다. 뒤집힌 결정도 근거가 남아 있어야 같은 논쟁을 두 번 하지 않는다.
- **새 번호는 `ls docs/adr/`로 실물을 확인하고 잡는다.** 이 목록만 보면 안 된다 — 동시 세션이 같은 번호를 쓰고 목록에 등재하지 않으면 충돌이 눈에 안 보인다(아래 0016 사례).

> ⚠️ **번호 충돌 미해결 (2026-08-01 식별)**: `0016`을 두 문서가 쓰고 있다 —
> `0016-glb-upload-presign-contract-local-port.md`(아래 목록에 등재됨)와
> `0016-auth-verification-boundary.md`(등재 안 됨). 둘 다 "ADR-0016"으로 인용되고 있어
> 코드 주석이 어느 쪽을 가리키는지 문서만 봐서는 갈리지 않는다 — 인용처는 auth 쪽이
> 압도적으로 많다(백엔드 테스트 2파일 + 프론트 e2e 10파일 이상이 "ADR-0016 결정 3·4·5"로 참조).
> 개명은 인용처 일괄 수정이 따라오므로 **별건**으로 처리한다. 그때까지 새 번호는 `0018`부터 잡을 것.

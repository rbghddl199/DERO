# ADR-0033. 데스크피드 전용 도메인 — 마커 해시태그 폐기, 사진 우선 + 배치 단일 FK

## 상태

**확정** — 2026-08-10, 승인 박동규 (그릴링 세션) · **결정 2는
[ADR-0034](0034-desk-feed-post-parity.md)가 대체**(2026-08-11 — 제목·마크다운 본문·인라인
이미지, post 동형 전환. 결정 1·3·4·5·6은 유효). 기획급 근거는 `docs/CONTEXT.md` D32,
스키마 정본은 `docs/context/erd.md` `desk_feed` 절. [ADR-0013](0013-placement-embed-as-content-token.md)의
"역방향 조회 요구가 생기면 그때"가 이 ADR로 실현됐다(단 정션이 아니라 단일 FK — 결정 3).
[ADR-0011](0011-post-as-separate-axis-from-placement.md)의 대상별 테이블 원칙을 세 번째로 적용한다.

## 맥락

데스크피드(실사 사진 갤러리, REQ-COM-16)는 2026-08-10 오전 "백엔드 무변경" 제약 아래
**post + 예약 해시태그 `데스크피드`** 구조로 출시됐다 — ERD가 동결돼 있었고 언락 사유가
그때는 없었다. 같은 날 기획 확장(사진 ↔ 3D 배치 양방향 연결)을 그릴링하며 재검토한 결과,
마커 구조의 구조적 결함 4건이 확인됐다:

1. **사용자 태그 필터 불가** — `GET /posts?hashtag=`는 단일 파라미터인데 마커가 점유한다.
   인스타그램식 태그 탐색이 원천 봉쇄.
2. **커뮤니티 목록 페이지 구멍** — 서버에 exclude 필터가 없어 `getCommunityPostPage`가
   받은 페이지에서 마커 글을 클라이언트로 뺀다. 데스크피드 글이 늘수록 커뮤니티 페이지가
   얇아지고, 한 페이지 전부가 마커 글이면 빈 페이지가 온다.
3. **마커 충돌** — 커뮤니티 작성 폼에서 `데스크피드` 태그를 수동 입력하면 글이 커뮤니티에서
   사라지고 데스크피드에 출현한다. 차단 장치 없음.
4. **가짜 댓글** — post 댓글 엔드포인트가 미구현이라(`PostController`에 CRUD 5개뿐,
   `PostComment` 엔티티만 존재) 데스크피드·커뮤니티 댓글이 세션 메모리다. 새로고침하면 증발.

동시에 신규 요구 두 가지가 스키마 자리를 요구했다: **배치 첨부**(사진 먼저, 배치 나중 —
양방향)와 **역방향 조회**("이 배치의 실사 사진"을 컬렉션 배치 상세에). 역방향은 현 구조로
답할 수단이 없다 — posts ES 인덱스는 배치 토큰을 색인에서 걷어내고(ADR-0027), `content`
LIKE 스캔은 인덱스 불가라 프로덕션 부적격이다.

운영 데이터는 데스크피드 글 1건, 전체 post 5건 — 구조 전환 비용이 사실상 0인 시점이다.

## 결정

### 1. 전용 `desk_feed` 도메인 — post 재사용 폐기

신설 5테이블: `desk_feed` · `desk_feed_image` · `desk_feed_like` · `desk_feed_comment` ·
`desk_feed_hashtag`. `post` 계열·`placement`는 무변경. 좋아요·댓글을 별도 테이블로 두는
근거는 ADR-0011과 같다(D24 대상별 분리 + `CHECK` 미사용이라 다형성 FK의 배타를 DB가 못
지킨다). 마커 상수(`constants/deskFeed.ts`)·매퍼 strip·커뮤니티 클라 필터는 프론트에서
제거한다 — 결함 2·3이 원천 소멸하고, 1은 `desk_feed_hashtag`로, 4는 `desk_feed_comment`
실구현으로 처방된다.

**`post.type` 컬럼 절충안은 부결** — 데스크피드가 사진 우선 모델(결정 2)로 확정되며 post의
콘텐츠 모양(마크다운 `content`에 이미지 임베드)과 구조가 갈라섰다. 한 테이블에 두 콘텐츠
모델을 담으면 컬럼 절반이 타입별로 무의미해진다.

### 2. 콘텐츠는 사진 우선 — 에디터 없음

사진 1~10장(`display_order`, **0번이 목록 카드 대표**) + 캡션(선택, 플레인 TEXT) + 태그 ≤5.
제목·마크다운 본문·Tiptap 에디터 없음. 데스크피드의 존재 이유가 "3D 배치 → 상상도 플로우가
무거워 유입이 안 된다"인데, 리치 에디터가 바로 그 무게였다.

`post_image`와 반대로 `display_order`를 두고 `is_primary`를 안 둔다 — post는 본문 안 위치가
순서의 정본이라 순서 컬럼이 이중화였지만(ADR-0013), 데스크피드는 본문이 없어 순서 컬럼이
유일한 정본이다. 대표를 별도 플래그로 두면 그쪽이 정본 둘(순서·플래그)을 만든다.

### 3. 배치 연결은 단일 nullable FK — 토큰도 정션도 아니다

`desk_feed.placement_id BIGINT NULL` (FK → `placement`, ON DELETE SET NULL) +
`idx_desk_feed_placement_id`.

- **토큰(`[[placement:ID]]`)이 아닌 이유**: ADR-0013이 토큰을 택한 근거는 스토리 글의
  "여러 배치" 요구 + 본문 임의 위치 삽입이었다. 데스크피드는 본문이 없고, 사진 글 하나 =
  책상 하나 = 배치 하나다.
- **정션이 아닌 이유**: 카디널리티가 최대 1이라 정션은 과잉이다. N개 요구가 실제로 생기면
  그때 정션으로 푼다 — ADR-0013과 같은 판단의 반복.
- 역방향 조회("이 배치의 실사 사진")가 인덱스 하나로 성립한다. ADR-0013이 기록한 대가(LIKE
  스캔·FK 무결성 없음)를 이 도메인에서는 지불하지 않는다.

첨부 대상은 **작성자 본인의 `publish_status = PUBLIC` 배치만**(WAS 검증) — post 토큰 삽입과
같은 규칙(D25)이다. 비공개 배치 허용안은 부결: 공개 글 안에 열람 불가 배치가 생겨 클릭이
404가 되고, 읽기 전용 뷰 신설은 노출 술어 변경이라 대가가 크다. 컬렉션 공개(상상도 생성
+한도 차감)가 선행되는 문턱은 감수한다 — "상상도 없이 공개"가 진짜 수요면 컬렉션 쪽 별도
결정이다.

### 4. 양방향의 실체 — 자동화는 최소

- 사진 글 상세: 첨부 배치를 **요약 카드**로 렌더(3D 뷰어 임베드 부결 — 컬렉션 상세가 이미
  하는 일이고 사진 글 페이지에 엔진 로드가 붙는다) → 클릭 시 컬렉션 상세 이동.
- 컬렉션 배치 상세: "이 배치의 실사 사진" 섹션 — **데스크피드 글만** 노출(커뮤니티 스토리
  글은 그 책상 사진이 아닐 수 있어 "실사"의 의미가 흐려진다).
- 시뮬레이터 진입은 "이 사진으로 배치 만들기" 링크뿐. **자동 첨부 부결** — 배치가 PUBLIC이
  되는 순간 원글에 자동 연결하려면 "대기 중 연결" 상태 저장소와 비동기 실패 처리가 새로
  필요한데, 수동 첨부(수정 화면 피커) 대비 이득이 작다.
- 수정 화면 신설(캡션·사진·태그·배치 첨부/해제) — 첨부 단일 액션안 부결, `PUT` 하나로 같은
  비용이고 수정 부재는 어차피 알려진 구멍이었다.

### 5. 엣지 — 링크의 생애

- 배치 **삭제**: `SET NULL` — 사진 글은 남는다(`generated_image.placement_id`와 같은 판단).
- 배치 **공개취소**: FK 유지, 화면이 카드를 숨긴다. 역방향은 컬렉션 상세 자체가 PUBLIC
  전용이라 추가 처리 없이 성립한다.
- 댓글은 플랫(대댓글 없음) — `comment`·`post_comment`와 같은 결정.

### 6. 범위 경계

이번: 갤러리(매스너리+무한스크롤)·업로드·상세·수정·삭제·좋아요·댓글·정렬 탭(최신/인기)·
태그 칩. **후속**: 서버 검색(ES 색인 파이프라인이 붙어 무게가 다르다)·홈 랜딩 섹션(콘텐츠
1건인 피드를 홈에 걸면 빈 섹션이다 — REQ-COM-14의 숨김 규칙 덕에 나중에 추가가 싸다).
운영 마커 글 1건은 Flyway 마이그레이션이 `desk_feed`로 이관하고 마커 태그를 정리한다.
테이블 추가만이라 ADR-0026 확장/축소의 **확장 쪽**(배포 1회)이다.

## 대가

- 커뮤니티 post와 나란한 테이블 5개·API 한 벌·프론트 api 레이어가 새로 생긴다 — "비슷한
  갤러리 화면 둘"의 인프라가 두 벌이 되는 중복은 콘텐츠 모델이 갈라진 대가로 감수한다.
- 2026-08-10 오전 출시분(post 재사용 구현 — 갤러리 매퍼·마커 파이프라인·Tiptap 업로드 폼)의
  상당 부분이 당일 폐기된다. 정직하게 적는다: ERD 동결을 우회하려는 선택이 하루짜리 구현을
  낳았다 — 동결의 목적(조용한 변경 방지)은 지켜졌지만, "스키마를 안 건드리는 게 항상 싸다"는
  전제는 이번에 틀렸다.
- 데스크피드 글은 커뮤니티 검색(`GET /posts?q=`)에서 빠진다 — 전용 검색은 후속(결정 6).

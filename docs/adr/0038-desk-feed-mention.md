# ADR-0038. 데스크피드 멘션 — 본문 내 안정 userId 토큰

## 상태

**확정** — 2026-08-11, 승인 박동규 (그릴링 세션). 기획급 근거는 `docs/CONTEXT.md` D35.
**스키마 변경 없음** — `docs/context/erd.md` 불변. 본문 형식은 에디터 회귀(D34·ADR-0037,
MR !530 — 이 ADR 작성 시점 미머지)가 다시 바꾸는 중이므로, **구체 토큰 직렬화는 그 작업이
확정한 콘텐츠 포맷에 맞춰 구현 시점에 확정**한다. 구현은 에디터 회귀(에픽 593) 머지 후
에픽 600에서 한다.

## 맥락

- **크레딧 시나리오**: A가 B의 데스크 사진을 찍어 올리며 "@B 꺼입니다!"라고 주인을 밝힌다.
  데스크피드의 배치 첨부는 **본인** 공개 배치만이라(D32) 남의 데스크를 올릴 때 출처를 밝힐
  구조적 수단이 없다 — 멘션이 그 공백을 채운다.
- 용어는 **멘션**이다. "태그"는 해시태그 뜻 전용(GLOSSARY)이고 "사용자 태그"조차 *사용자
  입력 해시태그*라는 다른 뜻을 이미 점유했다.
- 알림 시스템은 백엔드에 없다(0건). 사용자 검색 공개 API도 없다 — ES `users` 인덱스
  (닉네임 + autocomplete 필드)는 내부 필터용으로만 존재한다(ADR-0027).
- **닉네임은 변경 가능하고 unique다**(`changeNickname()`). 버려진 닉네임을 제3자가 선점하면
  생 텍스트 `@닉네임` 멘션이 **조용히 다른 사람을 가리킨다** — 크레딧 기능에서 치명적.

## 결정

1. **본문·댓글 텍스트 멘션.** 자동완성으로 사용자를 선택하는 순간 텍스트에 **안정 userId
   토큰**을 삽입한다. 문법은 `[[user:ID]]`(구현 확정) — 게시글 본문 토큰 `[[placement:ID]]`(D25)와
   동형. 렌더는 항상 **현재** 닉네임을 표시하므로 닉변에 안전하다.
2. **효과는 프로필 링크 렌더만.** 멘션이 `/users/{id}`로 링크된다. 서버가 응답 DTO에
   `mentions: [{userId, nickname}]` 해석 목록을 동봉하고 프론트는 치환만 한다.
3. **닉네임 자동완성 API 신설**: 로그인 사용자만, 최소 1자, 결과 ≤10, ES `users` 인덱스
   재활용. (컬렉션 검색의 "작성자는 별도 섹션이 아니다"(ADR-0027 결정 2)와 다른 표면이라
   충돌 없음.)
4. **탈퇴 사용자는 "@알 수 없음"** + 링크 제거 — `DeskFeedCommentResponse`의 탈퇴 작성자
   관례와 동형.
5. **전제 작업**: 데스크피드 작성자·댓글 작성자 닉네임에 프로필 링크를 건다(현재 plain
   `<span>` — 멘션과 무관하게 구멍).

## 부결

- **생 텍스트 `@닉네임` 저장** — 닉네임 재사용 시 멘션이 다른 사람을 가리킨다(맥락 참조).
- **멘션 정션 테이블** — 렌더만 하는 현 요구에 과함 + erd 동결. "멘션된 글 모아보기" 요구가
  생기면 저장된 토큰을 파싱해 백필로 승격 가능하므로 지금 만들지 않는다.
- **알림** — 알림 인프라 자체가 없어 신설이 별건(에픽급). 크레딧의 반쪽(B가 자기 데스크가
  올라간 걸 모른다)이 비는 것을 알고 미룬다.
- **구조화된 "데스크 주인" 필드**(인스타 사람 태그형) — 새 컬럼·작성 UI가 더 들고, 사용
  방식이 본문 문장 안 표기라 텍스트 멘션이 그대로 맞는다.

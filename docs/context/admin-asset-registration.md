# 관리자 에셋·발광 등록 가이드 (온보딩)

> 대상: 제품을 관리자 콘솔에 올리는 사람. **GLB를 어떻게 굽고 어드민에서 무엇을 어떤 순서로 채우는가**만 다룬다.
> 절차 안내서다 — 상세·판정은 정본이 우선: 저작 `asset-pipeline.md` · 룩 `glb-rendering-guide.md` · 렌더 결정 `lighting-map.md` · 스키마 `erd.md` · 화면 흐름 `../USER-FLOWS.md`.
> 핵심 한 줄: **발광은 `spec_type`과 직교다.** 조명이든 RGB 키보드든 어드민에서 같은 폼(`product_emitter`)을 쓴다. 갈리는 건 **GLB를 어떻게 굽느냐**다.

## 0. 먼저 판단 — 내 제품은 어느 갈래인가

| 갈래 | 예 | GLB에 굽는 것 | 어드민 발광 설정 |
|---|---|---|---|
| **A. 조명 제품** | 스탠드, 데스크램프, 모니터라이트, 스크린바 | `light_origin` 노드 + `lampShade` 이름. **emissive 안 굽는다** | **필수** |
| **B. 가변 발광**(리컬러) | 키보드 백라이트, PC 케이스 RGB | 발광 메쉬 분리 + `emitterSurface: true`. **emissive 안 굽는다** | **필수** |
| **C. 고정 발광** | 전구 유리, 고정 LED 인디케이터 | **emissive를 ×20으로 굽는다** | 없어도 된다 |
| **D. 발광 없음** | 의자, 책, 화분 | 일반 GLB | 안 만든다 |

**갈래는 물체 종류가 아니라 "사용자가 조절하는가"로 갈린다.** 조명(밝기·색온도 조절)과 리컬러 발광이 같은 편에 서는 이유가 이것이다 — 조절 대상 값은 GLB에 구우면 안 되고 런타임이 주입한다.

C는 자기만 빛나고 주변을 못 비춘다(emissive는 주변을 안 비춘다 — 실측 패널 255, 바로 아래 바닥 0.00). 발광면이 책상에 빛을 뿌려야 하면 C가 아니라 A·B로 올려 `product_emitter` 행을 만들어라.

**관절 축은 이 표와 직교다.** 모니터암은 발광이 없어 D지만 리그 매니페스트 저작(§3)이 필요하고, 발광하는 관절 제품이 나오면 둘 다 한다.

**예외 — 책상(`DESK`)과 모니터(`MONITOR`)는 GLB가 없다.** 규격 mm로 런타임 절차 생성이라(D18 — 모니터는 2026-08-02 재개정으로 화면 패널·베젤·스탠드가 전부 절차 생성) 어드민에 에셋 섹션 자체가 안 뜬다. 책상 상판 재질은 `desk_texture` 선택이 정본이고, 모니터 재질은 코드 상수다.

## 1. GLB 굽기

### A. 조명 제품

**AI 생성(Meshy 등) 금지** — 광학 규격을 못 만든다 (D5).

1. **`light_origin` 빈 노드 1개.** 메쉬·자식 없는 glTF Empty, 이름은 **정확히 `light_origin`**, 제품 로컬 좌표(미터). 광원이 실제로 있어야 할 자리(갓 안쪽 위)에 둔다.
   - 갓·격자·셰이드 같은 **차폐 기하가 있으면 필수.** 없으면 런타임이 bbox 중심으로 폴백하는데 램프의 bbox 중심은 **폴대 중간**이라 조용히 틀린다.
   - 모니터라이트·스크린바는 제품 전체가 곧 발광 바라 bbox 중심이 맞다 — 노드 없어도 된다.
   - **개명 = 파괴적 변경.** 런타임 정본은 노드가 아니라 DB(`point_*_mm`)지만, 노드를 두는 값은 저작 정확도와 검수다(갓을 옮기면 노드가 같이 옮겨져 아래 조건이 깨진 게 보인다).
2. **차폐 기하 메쉬 이름에 `lampShade`.** 빛 무늬(쿠키) 베이크는 이 이름의 메쉬만 굽는다. 복수 가능. 이 이름이 없으면 무늬 없이 정상 렌더된다(에러 아님).
   - **받침·폴·바닥판을 이 이름에 넣지 마라.** 쿠키는 그림자와 달리 깊이가 없어 광선 위 첫 히트 표면까지 어둡게 만든다 — 광원 바로 아래 받침을 차폐물로 구우면 **받침 자기 윗면이 검게 죽는다.** 받침이 상판에 드리우는 진짜 그림자는 그림자 캐스터 슬롯이 따로 처리한다.
3. **갓이 빛을 실제로 깎으려면 `atan(rBot / H) < 빔 반각`.** `rBot` = 갓 아랫테 반경, `H` = `light_origin`에서 갓 아랫테까지 깊이. 빔 반각은 어드민에서 고르는 배광 프리셋이 정한다(정본 `frontend/src/three/scene/lighting.ts`).
   - 안 지켜도 **등록은 통과한다.** 얕은 접시형 갓·오픈 셰이드는 실물에 있고 그런 제품은 무늬가 없는 게 사실이다. 어드민이 경고만 띄운다.
   - 갓이 기울어 있으면 차단각이 방위마다 갈린다 — 한 값이 아니라 범위로 봐야 한다.
4. **발광면에 emissive를 굽지 않는다.** 사용자가 밝기 배율·색온도를 조절한다(D5·REQ-SIM-08).
5. **쿠키 마스크 PNG를 만들지 마라.** 런타임이 갓 기하에서 제품별 1회 굽는다 — 납품물도 컬럼도 파일도 없다.

### B. 가변 발광 (리컬러)

- **원리: 마스크가 아니라 지오메트리가 가린다.** 발광 파트를 별도 메쉬로 두고 비발광 파트가 물리적으로 덮으면, 보이는 빛 = 틈새다. emissive 텍스처 페인팅 불필요.
- 키보드 기준 세그먼트 3개: `case` / `plate`(발광면) / `keycaps`(뭉치 1개 — 키 단위 분리 금지). 융합 금지.
- **발광 지정 = 발광 메쉬 노드에 glTF extras `emitterSurface: true`** (Blender 커스텀 프로퍼티 1개).
  - 표시가 없으면 **전 메쉬 발광 폴백**이다 — 키보드가 백라이트가 아니라 통째로 빛나는 플라스틱 덩어리가 된다.
- **emissive 맵을 굽지 않는다.** 색·세기는 런타임이 `placed_item.emitter_color`로 주입한다.
- **세그먼트별 재질을 분리해라.** gltfpack은 동일 재질 메쉬를 병합한다 — 재질이 같으면 분리해 둔 세그먼트가 압축에서 다시 붙는다.

### C. 고정 발광

- 전구·LED 같은 고정 발광면은 emissive 채널 **필수**. 런타임 노출이 1/20이라 **값을 ×20으로 저작**한다. 안 그러면 발광이 안 보인다.
- 색공간: emissive = sRGB.
- 발광 설정을 안 만들면 GLB 자체 emissive만 보이고 주변을 안 비춘다. 그게 의도면 그대로 두면 된다.

### 공통 — 압축

`scripts/asset-pipeline.sh <in.glb>` 한 줄이 정답이다. 손으로 gltfpack을 돌리면 **두 플래그가 발광을 조용히 죽인다**:

| 플래그 | 없으면 | 대상 |
|---|---|---|
| `-ke` | extras 폐기 → `emitterSurface`가 사라진다 | B |
| `-kn` | 메쉬 없는 노드 제거 → `light_origin`이 사라진다(출력 노드가 이름 없는 하나로 뭉개진다) | A |

`-kn` 대가는 실제 에셋 5.1 MB에서 **+40 B**다. `-km`은 불필요(발광면과 살은 재질이 필연적으로 다르다).

**압축 후 검수 2줄**
- `light_origin` 노드 생존 확인 (`-kn` 회귀 방어)
- `product_emitter` 행이 있는 제품의 에셋은 `emitterSurface` 플래그 메쉬 ≥1

## 2. 어드민 등록 절차 — 순서 고정

순서를 지켜야 하는 이유: 좌표 자동 추출과 미리보기가 **등록된 GLB URL을 요구**한다. GLB 없이 발광부터 채우면 두 도구가 안 열려 좌표를 손으로 재게 된다.

1. **제품 생성** — `/admin/products/new`. 브랜드·카테고리·이름·가격 등 공통 정보 + `spec_type`.
2. **규격 저장** — `spec_type = LIGHT`면 조명 규격 폼이 뜬다.
   - 필수는 **크기 3종(가로·깊이·높이)뿐.**
   - 색온도 K·정격 광속 lm·배광·정격 도달 거리는 **제품 상세에 찍히는 카탈로그 표기다. 렌더가 읽지 않는다.** 스펙시트에 없으면 **비워라 — 지어내지 마라.**
3. **3D 에셋 (GLB) 섹션** — `/admin/products/{id}` 아래.
   - `[GLB 올리기]` → presign 발급 → 스토리지 직접 PUT → `assetKey` 확보.
   - **GLB export 모드**: `PART_SEGMENTATION`이면 **재질 프리셋 필수**(투명 아크릴/메탈릭/화이트/블랙), `TEXTURE`면 **반드시 비움**(GLB가 재질 정본). 조명·발광 제품은 보통 `TEXTURE`다.
   - 폴리곤 수는 선택.
   - **저장을 눌러야 `assetKey`가 박힌다.** 업로드만 하고 저장 안 하면 다음 단계 도구가 안 열린다.
   - 이미 등록된 에셋은 재업로드 없이 메타만 고쳐 저장할 수 있다. 파일 교체도 같은 PUT.
4. **관절이 있는 제품이면 리그 매니페스트 저작** — §3. 관절이 없으면 건너뛴다.
5. **발광 설정 섹션** — §4 필드 채우고 `[발광 저장]`. 갈래 D면 건드리지 않고 지나간다.
6. **확인** — §6 체크리스트.

## 3. 리그 매니페스트 저작 (관절 에셋만)

대상은 **모니터암·마이크암·노트북 거치대·휴대폰 거치대**처럼 관절이 있는 제품이다. 관절이 없으면 이 자리를 비워 둔 채 등록해도 된다.

산출물은 `asset.rig_manifest` 한 덩어리다: **어떤 메쉬가 어떤 논리 세그먼트인지 + 세그먼트끼리 어떤 관절로 물리는지.** 런타임이 이걸 읽어 피벗 노드를 세우고 FK 체인을 만든다.

### 3-1. GLB 저작 조건

- **part-segmentation export**(융합 단일 메쉬로는 관절이 불가능하다). Meshy 산출물도 part-seg면 허용된다 — 조립은 아래 매니페스트가 한다.
- 세그먼트별 **분리 메쉬**, 각 원점을 **관절 축에 정렬**, 부모-자식 페어런트 체인 구성.
- **안정된 노드 이름.** 런타임이 이름으로 관절을 찾는다 — **개명 = 파괴적 변경**이다. 매니페스트가 이름을 들고 있으므로 GLB만 다시 export하고 이름이 바뀌면 저작이 통째로 낡는다.
- Apply Scale = 1, 미터. **한계각을 메쉬에 넣지 않는다** — 규격 DB(여기 매니페스트)가 정본.
- **스키닝 금지.** 리지드 노드 계층 + 런타임 FK다.
- **텍스처를 굽지 않는다.** part-seg는 텍스처를 못 받는다 — 재질은 에셋 등록의 `finish` 4종에서 고른다. 텍스처가 필요해 TEXTURE로 재export하는 순간 관절을 잃는다.
- 압축은 `asset-pipeline.sh`. 손으로 돌린다면 **`-kn -km`** 이 필요하다(노드 이름·메쉬 보존 — 이름이 죽으면 매니페스트가 아무 메쉬도 못 찾는다).

### 3-2. 도구 여는 법

에셋 섹션에서 **GLB를 먼저 등록**하고(§2 3단계), export 모드가 `PART_SEGMENTATION`일 때 리그 저작 도구가 열린다.

- **이 화면의 로더는 KTX2를 붙이지 않는다.** 텍스처가 박힌 GLB를 열면 통째로 실패하는데, 그건 로더 문제가 아니라 **그 GLB가 관절 에셋이 아니라는 신호**다. export 모드를 다시 확인해라.
- 화면은 **위 3D 미리보기 / 아래 좌 파트·세그먼트 패널 · 우 관절 패널 / 맨 아래 포즈 바**다.

### 3-3. 순서

1. **세그먼트를 만든다.** 좌 패널 위 `새 세그먼트 이름` + `[+ 세그먼트 추가]`. 이름은 논리 이름이다(`clamp-base`, `lower-arm`, `head-mount` 같은 식).
2. **파트를 세그먼트에 배정한다.** `mesh_0`…`mesh_N` 각 행의 셀렉트에서 고른다. 행에 마우스를 올리면 3D에서 그 메쉬가 하이라이트되므로 **이름이 generic해도 눈으로 찾을 수 있다**(Meshy는 `model_partN`처럼 뜻 없는 이름을 준다).
   - **한 메쉬는 한 세그먼트에만 속한다.** 다른 세그먼트로 옮기면 이전 소유에서 자동으로 빠진다. 중복 소유는 검증이 반려한다.
   - 배정하지 않은 메쉬가 남아도 검증은 통과한다 — 다만 그 메쉬는 리그 루트에 고정된다.
3. **지지 세그먼트를 고른다**(`supportPart`). 좌 패널의 `지지 세그먼트` 셀렉트. **책상 상판 안에 있어야 하는 파트**다 — 클램프·베이스를 고른다. 이 파트의 footprint만 상판 안이면 되고 **상부는 상판 밖으로 뻗어도 된다**(캔틸리버 허용).
4. **결합 세그먼트를 고른다**(`mountPart`). 좌 패널의 `결합 세그먼트` 셀렉트. **모니터가 물리는 파트**다 — 헤드·마운트를 고른다. 자석 결합(D22)에서 모니터가 매달리는 부모가 이 세그먼트다. 관절만 있고 다른 제품이 물리지 않는 에셋은 비워 둔다.
5. **관절을 만든다.** 우 패널 상단에 `관절 id` · `표시명` · `부모 세그먼트` · `자식 세그먼트`를 넣고 `[+ 관절]`.
   - **`관절 id`는 네가 짓는 문자열이다 — DB의 PK가 아니다.** 그 매니페스트 안에서만 유일하면 되고 다른 제품이 같은 id를 써도 무관하다. `<부위>-<동작>` kebab-case ASCII로 쓴다(한글·공백·`joint1`·GLB 노드 이름 금지 — 한글은 `표시명` 담당).
     - 부위는 세그먼트 이름 계열을 따른다(`clamp-base` → `base-`, `head-bracket` → `head-`).
     - 동작은 **`arm` 테이블 각도 컬럼과 어휘를 맞춘다**: `tilt`·`swivel`·`pivot`. 그 밖은 축 용어 `yaw`(Y)·`pitch`(X)·`roll`(Z). 직선 관절은 `column-lift`·`tray-slide`처럼 동작 이름으로 — 단위가 mm라 각도 어휘를 쓰면 거짓 이름이 된다.
     - 현행 모니터암 5개가 예시다: `base-yaw` · `elbow-pitch` · `head-tilt` · `head-swivel` · `head-pivot` (`frontend/src/three/scene/product.ts`).
     - **id는 배치 데이터가 참조한다** — `placed_item.joint_values`의 키이자 종속 관절의 driver 참조다. 이미 배치된 제품의 id를 바꾸면 저장된 포즈가 조용히 고아가 된다. 메쉬 개명과 같은 파괴적 변경이다.
   - **부모·자식은 세그먼트지 메쉬가 아니다.** 세그먼트를 먼저 만들지 않으면 셀렉트가 비어 있다.
   - 자식 = 움직이는 쪽. 관절 순서가 곧 체인 순서다 — 런타임은 "자기 부모 세그먼트를 자식으로 갖는 가장 가까운 이전 관절" 아래에 매단다. 같은 피벗에 관절 둘을 겹쳐 쌓는 것(베이스 yaw + 숄더 pitch)도 이 규칙으로 동작한다.
6. **관절을 편집한다.** 관절 행을 펼치면 3D에 피벗 구슬과 축 화살표가 뜬다.
   - **축** — X/Y/Z 버튼. 저장되는 값은 단위벡터라 길이가 1이 아니면 반려된다.
   - **피벗 x/y/z** — 기본값은 **부모∩자식 bbox 교집합의 중심을 제안한 값**이라 실측 대비 **2~12 mm 어긋난다.** 출발점으로 쓰고 Y·Z를 손보는 것이 정상 절차다. 두 bbox가 떨어져 있으면 중심의 중점으로 떨어지는데 이건 더 거친 추정이라 UI가 경고한다.
   - **한계** — 회전(`revolute`)은 도, 직선(`prismatic`)은 mm. **정지 포즈 0이 반드시 범위 안에 들어야 한다** — `min > 0`이거나 `max < 0`이면 반려다.
   - **종속(coupling)** — 다른 관절을 따라가는 관절. `값 = driver × ratio + offset`이고 계산 뒤 자기 한계로 다시 클램프된다(ratio를 잘못 넣어도 파트가 뒤집히지 않게). **종속 관절을 또 종속시킬 수는 없다**(체인 금지). 저장되는 것은 driver 값뿐이고 종속값은 로드할 때 다시 계산된다.
7. **움직여 본다.** 맨 아래 포즈 바 슬라이더. **driver 관절만 뜬다** — 종속 관절은 사용자가 만지는 대상이 아니다. `[정지 포즈]`로 전부 0으로 되돌린다. 검증을 통과하지 못하면 미리보기가 움직이지 않는다.
8. **`[매니페스트 저장]`을 누른다.** 검증을 통과할 때만 열린다.

### 3-4. 검증이 반려하는 것

`검증 오류 N건` 배지를 누르면 목록이 펼쳐진다. 반려 사유는 이게 전부다:

- 한 메쉬가 두 세그먼트에 들어 있다
- 관절 id 중복 / 표시명이 비어 있다
- 부모·자식 세그먼트가 세그먼트 목록에 없다
- 축이 단위벡터가 아니다
- 종류에 맞지 않는 한계 필드(회전인데 `minMm`, 직선인데 `minDeg`)
- `min < max`가 아니다 / 정지 포즈 0이 범위 밖이다
- 자기 자신에 종속 / 없는 관절에 종속 / 종속 관절에 다시 종속

### 3-5. 함정

- **`[매니페스트 저장]`과 `[에셋 저장]`은 다른 버튼이다.** 위쪽 에셋 저장은 매니페스트를 건드리지 않고, 관절 편집은 매니페스트 저장으로만 반영된다.
- 세그먼트를 지우면 **그것을 부모·자식으로 쓰던 관절도 같이 지워진다.** 지지·결합 세그먼트 지정도 함께 풀린다.
- GLB를 새로 올려 메쉬 이름이 바뀌면 저장된 매니페스트가 **조용히 낡는다**(이름으로 찾기 때문). 재export 때 이름을 보존해라.

## 4. 발광 설정 필드 (`product_emitter`)

**여기가 렌더 정본이다.** 조명 규격 폼의 광학 값과 이름이 비슷한 필드가 둘 있는데 서로 다른 값이다 — 아래 표 마지막 열을 봐라.

| 필드 | 규칙 | 헷갈리는 것 |
|---|---|---|
| **발광 형태** | `POINT` / `SPOT` 필수 | **POINT는 그림자 배정에서 빠진다** — 큐브맵이라 씬을 여섯 번 그려야 한다. 갓으로 원뿔을 쏘면 SPOT |
| **배광 프리셋** | **SPOT일 때만 필수. POINT면 비워야 저장된다**(조일 원뿔이 없다). `SPOT`집중형 / `FLOOD`확산형 / `AMBIENT`간접광 | 원뿔 각·penumbra 수치는 코드가 정본 — 이름 하나만 고른다. 조명 규격의 '배광'과 다른 칸이다 |
| **저작 기준 광속 (lm)** | 필수, 양수 정수. 사용자 밝기 배율을 곱하기 **전** 값 | 제조사 정격 lm이 아니다. 눈으로 맞춘 값이어도 된다(현행: 램프 400~560, 장식 발광 30~45) |
| **도달 반경 (mm)** | 필수, 양수 정수. 빛 컷오프 | 조명 규격의 '정격 도달 거리'와 다른 값 |
| **색 변경 가능** | **미선택 저장 불가** | `false`로 둔갑하면 색 선택 UI가 사용자에게 **아예 안 뜨고**, 사용자는 왜 안 뜨는지 알 방법이 없다 |
| **기본 발광색** | `#RRGGBB` 6자리 필수 | 색을 못 고르는 제품에선 이게 최종색, 고를 수 있는 제품에선 초기값 |
| **발광 지점 X/Y/Z (mm)** | **셋 다 채우거나 셋 다 비운다.** 정수 mm, 음수 가능 | 비우면 bbox 중심 폴백 — **갓 있는 램프는 폴대 중간이 되어 조용히 틀린다.** 모니터라이트는 폴백이 맞다 |

**Z 주의**: 발광면 바로 위에 두면 글로우 한가운데 핫스팟이 박힌다. 살짝 안쪽으로.

**빛을 안 내게 되돌리려면** `[발광 삭제]`(DELETE). 에셋은 반대로 삭제가 없다 — "에셋 없음"이 유효한 건 책상·모니터뿐이고 둘은 에셋 섹션이 아예 안 뜨므로, 나머지 제품에는 교체만 있다.

## 5. 자동 도구 둘 — 답하는 질문이 다르다

GLB가 등록돼 있어야 열린다.

**`[GLB에서 light_origin 읽기]` — "노드가 있나"**
GLB를 열어 `light_origin` 좌표를 mm 정수로 변환하고, `[발광 좌표에 채우기]`로 X/Y/Z 세 칸을 채운다. mm 정수 옆에 반올림 전 미터 값을 같이 보여주니 눈으로 검산해라. 동시에 `lampShade` 차단각을 현재 배광 프리셋의 빔 반각과 견줘 "이 갓은 무늬를 내지 않는다"를 경고한다 — **경고는 등록을 막지 않는다.**

**`[발광 미리보기 열기]` — "어떻게 보이나"**
시뮬레이터와 **같은 조명 리그·노출·블룸**으로 그린다. 저장 안 해도 입력 즉시 반영된다.
**조명 값은 값으로 못 정하고 눈으로 정해진다** — 광속·색은 여기서 확정해라. 여기서 고른 값이 시뮬레이터에서도 그대로다.

## 6. 흔한 사고 체크리스트

- [ ] 조명인데 **발광 지점을 비웠다** → 광원이 폴대 중간에 박힌다. 램프는 반드시 채워라
- [ ] 손으로 gltfpack 돌려 **`-ke`/`-kn` 누락** → 발광 지정·광원 노드가 에러 없이 사라진다. `asset-pipeline.sh`를 써라
- [ ] `emitterSurface` 표시를 잊음 → 제품이 통째로 빛난다
- [ ] 조명·리컬러 제품에 **emissive를 구움** → 사용자 조절과 이중으로 걸린다
- [ ] `product_emitter`를 안 만듦 → 발광면이 빛나 보여도(GLB emissive) **주변을 안 비춘다**
- [ ] 조명 규격 폼의 lm/K를 **채워놓고 렌더에 반영되길 기대** → 그건 카탈로그 표기다. 렌더는 발광 설정만 본다
- [ ] `POINT`인데 배광을 골라둠 / `SPOT`인데 비워둠 → 422
- [ ] `PART_SEGMENTATION`인데 재질 프리셋 비움 / `TEXTURE`인데 채움 → 422
- [ ] '색 변경 가능'을 미선택으로 둠 → 저장 자체가 막힌다(막히는 게 정상이다)
- [ ] 받침·폴을 `lampShade`로 이름 지음 → 받침 윗면이 검게 죽는다
- [ ] 관절 편집만 하고 `[에셋 저장]`을 누름 → 매니페스트는 안 저장된다. `[매니페스트 저장]`이 따로다
- [ ] 관절 한계를 `10~90`처럼 잡음 → 정지 포즈 0이 범위 밖이라 반려된다
- [ ] GLB를 재export하며 메쉬 이름이 바뀜 → 저장된 매니페스트가 조용히 낡는다(이름으로 찾는다)

## 7. 등록 후 확인

1. 발광 미리보기에서 빛이 의도한 자리에서 나오는가 (핫스팟 위치·갓 무늬)
2. 시뮬레이터에 배치해 상판에 웅덩이가 지는가 — 미리보기와 같아야 정상
3. 리컬러 제품이면 색 선택 UI가 뜨고 색이 실제로 바뀌는가

**시각 판정은 사람이 한다.** 기계 게이트(422·검수 스크립트)를 통과했다고 룩이 맞는 게 아니다.

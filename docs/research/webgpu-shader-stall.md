# 실기 성능 실측 — 광원 집합 변경이 씬 전역 셰이더를 재빌드한다

> 2026-07-29 측정. 대상 DERO-235. 원시 데이터·스크립트는 `frontend/qa-artifacts/perf-diag/`(gitignore, 로컬 전용).

측정 환경: 맥 실기 GPU, Playwright `chromium.launch({ headless: false })`, **SwiftShader 인자 없음**.
`next build && next start`(prod) / `next dev`(dev) 양쪽. 디스플레이 120Hz(vsync 8.3ms).

## 0. 이 문서가 뒤집는 전제

- **실기 백엔드는 `webgpu`다.** 전 구간 `window.__sim.backend === 'webgpu'`. e2e·기존 프로브는 SwiftShader + **WebGL2 폴백**이라 셰이더 빌드 경로가 통째로 다르다 — **기존 e2e 성능 수치는 이 문제에 대해 아무 정보도 주지 않는다.**
- **회귀가 아니다.** "이슈 220 무렵부터 느려졌다"는 체감은 커밋 대조로 기각됐다(§4).
- **"로딩이 안 끝난다"는 재현되지 않았다.** 부팅은 dev·prod 모두 0.62~0.81초.

## 2. 아픈 건 광원 집합을 바꾸는 조작뿐

|---|---|---|---|
| mug 첫 배치 / 두 번째 | 25ms / **9.4ms(정상)** | +3 / 0 | 5→5 |

| **램프 1/2/3/4번째 배치** | 258 / **1301** / **1300** / **1425ms** | +3/+1/+1/**0** | 5→6→7→8→9 |
| 램프 삭제 / 비램프 삭제 | 108ms / 9.4ms(정상) | −1 / 0 | |
| **방 조명 OFF** / ON | **1175ms** / 117ms | **0** / 0 | 8→8 |
| 벽·컨투어·카메라·이동·회전·선택 (13종) | 전부 9.4~16.6ms(정상) | 0 | |

아이템 15개 씬에서는 램프 추가 1626/1675ms, 방 조명 OFF 1467ms. **22개 조작 1세션 누적 정지 6.2초.**

**프로그램 캐시 "증가"와 무관하다.** 램프 3·4번째와 방 조명 OFF는 캐시 크기 Δ가 0인데도 1.2~1.4초 멈춘다 — 새 프로그램이 추가되는 게 아니라 **기존 재질 셰이더가 통째로 교체·재빌드**된다. `frontend/src/three/CLAUDE.md:42-47`이 적어둔 `LightsNode` 언롤 + `castShadow` 해시 함정과 일치한다.

**초선형이고, 캐시된다.**

| 광원 전이 | 첫 등장 | 두 번째 이후 |
|---|---|---|
| 5→6 | 258ms | **33~58ms** |
| 6→7 / 7→8 / 8→9 | 1301 / 1300 / 1425ms | (§4의 2회차 실험에서 108~142ms) |

캐시는 브라우저 프로세스보다 오래 산다 — Playwright는 실행마다 새 프로필을 만드는데도 2회차가 빨랐다. macOS/Metal 드라이버 셰이더 캐시 계층으로 보인다.

> **[추론 · 미확증]** vsync를 끄면 같은 조작 스톨이 1.7초 → 108~142ms로 줄었다. 컴파일 CPU 작업량이 vsync에 따라 13배 변할 수 없으므로 스톨 대부분은 계산이 아니라 **프레임 프레젠테이션에 물린 GPU 동기 대기**로 보인다. 확증엔 WebGPU 파이프라인 생성 경로 트레이싱이 필요하고, 이번에 하지 않았다.

## 3. 무엇이 결백한가

vsync를 끄고(`--disable-gpu-vsync --disable-frame-rate-limit`, GPU는 여전히 실기 Metal) 기여를 분리했다.

| 조건 | p50 | 해석 |
|---|---|---|
| postfx ON + ~~그림자 ON~~ (현행) | 2.6ms | 기준 |
| postfx OFF | **0.5ms** | **postfx = 2.1ms (프레임의 81%)** |
| ~~그림자 OFF~~ | 2.6ms | ~~그림자 ≈ 0ms (노이즈 이하)~~ |
| 둘 다 OFF | 0.5ms | ~~그림자 기여 0 재확인~~ |

> ⚠️ **2026-07-29 정정 (DERO-248) — 위 표의 그림자 행 2개는 무효다.**
> 이 측정 당시 `renderer.shadowMap.enabled`가 **false**였다. `SimulatorCanvas.tsx`의 `<Canvas>`에 `shadows` prop이 없어 R3F가 `createRenderer()`의 설정을 덮어썼고(`shadows = false` 기본값 → `gl.shadowMap.enabled = !!shadows`), 2026-07-22 R3F 전환(`d251a42`) 이후 씬에 그림자가 한 장도 안 그려지고 있었다.
> 즉 "그림자 ON"과 "그림자 OFF"가 **같은 조건**이었고, 2.6ms가 양쪽에서 같게 나온 것은 그림자가 싸다는 뜻이 아니라 **양쪽 다 안 돌았다**는 뜻이다. `castShadow` 플래그는 정상이라 `lightingInfo()`도 e2e도 이상을 못 봤다.
> **실기 그림자 비용은 아직 측정된 적이 없다.** 248 수정 후 다시 재야 한다.

- **postfx는 프레임 비용의 압도적 다수지만 8.3ms 예산 안이라 지금 끄면 체감 이득이 0이다.** 저사양 기기를 볼 때의 첫 후보로 남는다. (이 항은 그림자와 무관하므로 유효하다 — 다만 그림자가 살아나면 프레임 총량이 늘어 81%라는 **비율**은 다시 재야 한다.)
- ~~**그림자는 사실상 공짜다.** 캐스터 캡(≤3)이 잘 듣고 있고 더 조여도 얻을 게 없다 — DERO-223의 M=3은 비용 측면에서 여유가 있다.~~ **(248이 폐기. M=3의 비용 여유는 근거가 없다.)**
- **R3F 리렌더 폭주는 없다.** React DevTools 훅을 앱보다 먼저 주입해 실제 커밋을 셌다: idle·선택 상태 10초 창에서 React 커밋 0, zustand 알림 0, rAF 1200프레임. `selectionAnchor`가 React 상태를 우회하는 설계가 의도대로 동작한다.
- 메모리 누수 징후 없음(geometries 26 · textures 64 · JS heap 86.5/146.8MB). 에셋 14개 5.3MiB, 콜드 요청 22~32ms.

## 4. 회귀가 아니다 — 변수는 "이 머신에서 처음 컴파일하는가"

`git worktree`로 과거 커밋을 별도 체크아웃해 같은 스크립트를 돌렸다.

| 실행 | 램프 추가 | 방 조명 OFF |
|---|---|---|
| `6480708`(07-25, 발광·글레어 이전) **1회차** | 1492/1542/1650/1734ms | 1533ms |
| `6480708` **2회차** (같은 코드·서버·스크립트) | **125/142/143/124ms** | **109ms** |
| `HEAD`(a6e962c) 2회차 | 108/125/125/142ms | 117ms |

세 커밋(07-25 / 07-26 / HEAD) 전부 1회차에 동일하게 스톨한다. **커밋이 아니라 셰이더 소스 해시가 이 머신에서 처음인가가 유일한 변수다.**

→ **그래서 개발자가 유독 심하게 겪는다.** 조명·재질 코드를 고치거나 새 커밋을 받을 때마다 캐시가 무효화되고, 광원 변형마다 다시 1.5~1.9초를 문다. dev HMR 편집이면 이 무효화가 반복된다. QA를 두 번째로 돌리면 멀쩡해 보인다 — **1회차 수치가 사용자 체감이고, 2회차 수치가 우리가 흔히 보는 화면이다.**

## 5. 못 잰 것

- **전송 바이트** — Next가 `content-length`를 안 붙여 전부 0. 디스크 실측(5.3MiB)으로 대체.
- **진짜 콜드 머신 첫 부팅** — macOS/드라이버 셰이더 캐시를 지우는 방법을 찾지 못했다. 부팅 수치는 전부 그 캐시가 어느 정도 더운 상태다.
- **스톨이 컴파일 CPU인지 GPU 동기 대기인지** — §2 말미의 추론에 그친다.
- **저사양·타 기기** — 이 측정은 맥 실기 1대뿐이다.
- **"로딩이 안 끝난다"** — 재현 실패. 한 번 180초 타임아웃이 났으나 원인은 `127.0.0.1` 접속을 Next dev가 HMR 오리진으로 차단한 측정 쪽 함정이었다(`localhost`로는 1152ms 정상). **앱 결함 근거를 찾지 못했다.**
